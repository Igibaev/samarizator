# ИИ-компаньон (Focus Companion)

Компаньон для macOS, живущий в вырезе экрана: два белых глаза, две кнопки
и три обещания себе. Реализует `design.md` версии 1.2.

## Композиция

```
        ┌─────────── аппаратный вырез ───────────┐┌──── правое крыло 164pt ────┐
        │            (камера, пусто)             ││ 👀   ⏺ запись   ✦ саммари │
        └────────────────────────────────────────┘└────────────────────────────┘
                     ┌──── полка задач 288pt, по центру выреза ────┐
                     │ ○ Отправить предложение          18 мин     │
                     │ ○ Закончить дизайн               45 мин     │
                     │ ○ Разобрать заметки            1 ч 20 мин   │
                     └─────────────────────────────────────────────┘
```

- Крыло — **бесшовное** правое продолжение выреза: левая сторона прямая,
  скругляются только правые углы, цвет и высота совпадают с вырезом.
- Наведение на глаза раскрывает панель фокуса (376 × 260) через 120 мс,
  уход курсора закрывает её через 450 мс.
- Свайп двумя пальцами влево: Фокус → Буфер → Записи, вправо — назад.
  Буфер и записи живут в одной правой панели шириной в половину экрана.

## Запуск

```bash
./build-app.sh              # сборка, упаковка в .app и запуск (только macOS)
```

Бинарник надо запускать **из терминала**: `open` не передаёт переменные
окружения, а почти вся отладка ими и управляется.

```bash
.build/release/FocusCompanion                       # обычный запуск
FOCUS_DEBUG=1 .build/release/FocusCompanion         # крыло красное — видно геометрию
FOCUS_DEMO=1 .build/release/FocusCompanion          # демонстрационные данные design.md §15
FOCUS_FIXTURE=threeTasks .build/release/FocusCompanion
FOCUS_BLINK_SEED=42 .build/release/FocusCompanion   # воспроизводимое моргание для скриншотов
SAMARIZATOR_HOME=/путь .build/release/FocusCompanion # другая база Samarizator
```

### Воспроизводимые состояния

Ждать реальных сроков не нужно. Меню в строке состояния → «Состояния для
проверки», или `FOCUS_FIXTURE=<имя>`:

| Имя | Что показывает |
| --- | --- |
| `empty` | Крыло без задач под ним |
| `threeTasks` | Канонические три задачи (18 мин / 45 мин / 1 ч 20 мин) |
| `oneFreeSlot` | Две задачи и свободный слот |
| `dueSoon` | Янтарный срок |
| `aboutToExpire` | Срок через 3 секунды — видно сгорание вживую |
| `expiredWithUndo` | Сгоревшая задача и кнопка «Вернуть» |
| `recordingInProgress` | Идёт запись: квадрат остановки и таймер |
| `summaryGenerating` | Генерация саммари: spinner вместо искры |
| `processingError` | Ошибка обработки записи |

«Вернуться к моим данным» в том же меню возвращает настоящие задачи.

## Что подключено к сервисам проекта, а что нет

| Возможность | Состояние |
| --- | --- |
| Список записей, транскрипт, саммари | **Настоящая интеграция**, только на чтение: `~/Library/Application Support/Samarizator/meetings.sqlite3` |
| Форматы «Кратко / Подробно» | Из полей `brief` / `detailed` саммари Samarizator |
| Формат «Действия» | Фильтр `kind == action` по тем же данным, отдельной генерации нет |
| История буфера обмена | **Настоящая**, `NSPasteboard`, включается явным действием пользователя |
| Начало записи, транскрибация, саммаризация | **Подключены** через headless-вход `python -m samarizator.companion`. Кнопка записи запускает и останавливает настоящую live-запись, кнопка саммари — настоящую сводку |
| Живой транскрипт | Текст появляется по ходу записи: компаньон опрашивает базу раз в 2 секунды |
| Снимок сводки во время записи | «По состоянию на 12:34»; когда распознано больше реплик, чем было на момент снимка, появляется «Обновить» |
| Готовность к работе | `companion status` отдаёт факты: есть ли модель Whisper, настроен ли адрес модели для сводки. Кнопка, которой нечем работать, говорит почему |
| Демонстрационный режим | Данные design.md §15, всегда подписаны как демонстрационные |
| Дела со встречи | **Настоящая интеграция** в обратную сторону: после сводки Samarizator кладёт согласованные поручения в `inbox/` папки компаньона, тот говорит об этом репликой на полоске под полкой, а «В фокус» берёт короткую формулировку из передачи |

Ничего из недоступного не маскируется правдоподобной заглушкой: выдуманных
процентов готовности и фиктивных успешных результатов в интерфейсе нет.

## Подключение к Samarizator

Компаньон сам ищет папку Samarizator: переменная `FOCUS_SAMARIZATOR_ROOT`,
затем сохранённый выбор, затем подъём вверх от бандла. Если не нашёл —
в панели «Записи» есть «Указать папку Samarizator…»: нужна та папка, где
лежит `start.sh`.

Своего Python компаньон не носит: он запускает интерпретатор из `.venv`
самого Samarizator, чтобы не разойтись с его зависимостями и моделью.

Проверить вход можно и без компаньона:

```bash
.venv/bin/python -m samarizator.companion status
.venv/bin/python -m samarizator.companion record --source both   # Ctrl+C останавливает
.venv/bin/python -m samarizator.companion summarize <id-записи>
```

## Дела со встречи и голос персонажа (Фаза 6)

Первый текст, который персонаж говорит сам. Кто он и как говорит —
`docs/focus-companion/CHARACTER-BIBLE.md`; техзадание — `PHASE-6-PROMPT.md`.

- `worker summary` в Samarizator (и из его GUI, и из `companion summarize`)
  после экспорта пишет `inbox/<meetingId>.json` в папку компаньона
  (`src/samarizator/handoff.py`) — только если папка уже существует.
  Поручения `kind == action`, `status == agreed`, из `resolved` или полного
  реестра, до пяти, без дублей и без того, что уже в слотах.
- Реплику и короткие формулировки сочиняет та же облачная модель по слоям
  промта (`character_prompts.py`: идентичность → характер → настроение →
  память → задача → формат). Тон проверяется списком запрещённых оборотов;
  не прошло — запасная реплика. Отказ модели сводку не ломает.
- `Model/HandoffInbox.swift` наблюдает за папкой (`DispatchSource`, запасной
  путь — тик напоминаний). `Model/MeetingHandoff.swift` — формат и
  отображение эмоций реплики (`calm`/`curious`/`happy`) в `CompanionState`.
- `TaskPanelController.handoffNotice` — реплика на компактной полоске
  (`CompactNoticeView`) с кнопкой «Открыть» (страница «Записи» с этой
  встречей) на 12 секунд; глаза реагируют через обычный `react`. Если человек
  отошёл, реплика ждёт его возвращения. Ничего не открывается само.
- `TaskPanelController.proposedTitle` — кнопка «В фокус» и замена при трёх
  занятых слотах берут формулировку из передачи, если она есть.
- Настройка в Samarizator: «Передавать согласованные дела ИИ-компаньону».
- Тесты Python-части: `tests/test_handoff.py`.

## Дневник в Obsidian

Задача помнит, с какой встречи пришла (`meetingId`, `sourceText` в
`tasks.json`; «В фокус» на странице «Записи» заполняет их сам).
`Services/JournalSync.swift` после каждого сохранения слотов (с паузой 3 с),
при запуске и раз в час вызывает `python -m samarizator.companion journal`.
Текст заметок собирает Python (`src/samarizator/journal.py`, тесты
`tests/test_journal.py`): заметка дня `Дни/<дата>.md` и `Поручения.md`.
Подробности — в корневом README, раздел «Дневник».

Проверка на живом Mac — [`docs/focus-companion/CHECKLIST.md`](../docs/focus-companion/CHECKLIST.md).

## Живость (бета)

`Character/LivelinessController.swift`, переключатель в меню, по умолчанию
выключен. Каждые 2 с смотрит на простой ввода (`IdleTimeProvider`): больше
5 минут — фон `asleep`, вернулся — реакция `waking`, 23:00–6:00 — `drowsy`.
Фон записи и обработки важнее покоя (`NotchWindowController.updateAmbient`).
Мелкие движения — `EyesViewModel.fidget()`, дыхание во сне — там же. Реплики
утром и вечером — `python -m samarizator.companion rhythm morning|evening`
(`src/samarizator/rhythm.py`, тесты `tests/test_rhythm.py`). Правила — в
библии персонажа, раздел «Живость».

## Проверка без Swift-тулчейна

```bash
python3 Tools/check_sources.py            # скобки, имена типов, статические члены
cd .. && python3 -m pytest tests/test_focus_companion_design.py -q   # сверка чисел с design.md
```

Headless-вход, в отличие от Swift-части, покрыт настоящими тестами:

```bash
uv run --extra dev python -m pytest tests/test_companion_cli.py tests/test_handoff.py tests/test_journal.py tests/test_rhythm.py -q
```

Обе проверки — структурные. Они ловят «переименовал и забыл» и дрейф чисел
раскладки, но **не заменяют сборку на macOS**.

Состояние: `swift build -c release` на машине автора проходит. Поведение в
рантайме не проверено — приложение после починки сборки не запускалось.

## Тон персонажа — требование, не украшение

У людей с СДВГ повышена чувствительность к критике. Поэтому:

- никакого стыда, счётчиков провалов и рвущихся «стриков»;
- позитивная реакция на выполнение ярче, чем негативная на просрочку;
- сгорание задачи — отпускание без вины: «Задача сгорела» и кнопка «Вернуть»,
  а не «Ты снова всё провалил»;
- компаньон **не отмечает задачу выполненной** без нажатия пользователя.
