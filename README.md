# Samarizator

Приложение для macOS: превращает аудио и видео в содержательные заметки с решениями, задачами
и таймкодами. **Всё работает на вашем Mac**: распознавание — **Whisper.cpp**, сводки —
**локальная языковая модель** через llama.cpp. Ни аудио, ни текст никуда не отправляются.
Формат итогового текста настраивается своим шаблоном. База знаний — папка Markdown для
**Obsidian с графом связей**.

**[Скачать для Mac](https://igibaev.github.io/samarizator/)** · [все версии](https://github.com/Igibaev/samarizator/releases)

## Установка — без установки

1. Скачайте `Samarizator-…-arm64.dmg` со [страницы загрузки](https://igibaev.github.io/samarizator/)
   или из [последнего релиза](https://github.com/Igibaev/samarizator/releases/latest).
2. Откройте `.dmg` и перетащите **Samarizator** в «Программы».
3. Запустите. Если macOS пишет «не удаётся проверить разработчика»: macOS 15+ —
   Системные настройки → Конфиденциальность и безопасность → «Всё равно открыть»;
   macOS 13–14 — правый клик → «Открыть». Один раз (не нужно, если сборка подписана
   Developer ID — см. [сборку](docs/packaging.md)).
4. На первом экране приложение покажет две модели, подобранные под ваш Mac: распознавание
   речи (Whisper) и модель сводок. У каждой видно, сколько она весит и сколько памяти (RAM)
   занимает во время работы. Нажмите **«Скачать модели и начать»** или выберите другие
   кнопкой «Другая». После загрузки интернет не нужен.

FFmpeg, whisper.cpp, VAD, llama.cpp и Python уже внутри приложения — Homebrew, Terminal и
Python не нужны. Модели в репозитории не хранятся и в `.dmg` не встраиваются: их скачивают
в приложении один раз, с докачкой после обрыва ([подробнее](models/README.md)). Нужен
macOS 13+ на Apple Silicon (M1 и новее).

### Какие модели выбрать

Модели работают по очереди, поэтому памяти нужно столько, сколько требует большая из них.
Память при работе — оценка приложения при настройках по умолчанию; модели, которые не
поместятся, в окне выбора недоступны.

**Распознавание речи.** По умолчанию предлагается **Whisper Podlodka Turbo** — large-v3-turbo,
дообученная на русской речи ([bond005/whisper-podlodka-turbo](https://huggingface.co/bond005/whisper-podlodka-turbo)):
расставляет пунктуацию, устойчивее к шуму и реже «выдумывает» текст в тишине. 1,6 ГБ на
диске, ≈ 2 ГБ памяти, подходит любому Mac от 8 ГБ. Для других языков есть обычные
large-v3, large-v3-turbo и лёгкие варианты.

| Память Mac | Сводки и вопросы (рекомендуется) | Другие варианты |
|---|---|---|
| от 32 ГБ (например, M4 Pro / 48 ГБ) | Gemma 4 26B-A4B — 16,9 ГБ, ≈ 23 ГБ памяти | Qwen3 30B-A3B — 18,6 ГБ |
| 16–24 ГБ | GigaChat 3.1 Lightning — ≈ 6,4 ГБ, ≈ 11 ГБ памяти, самая быстрая | Gemma 4 12B — 7,1 ГБ, аккуратнее |
| 8 ГБ | Qwen3 4B Instruct — 2,5 ГБ, ≈ 6,5 ГБ памяти | — |

GigaChat Lightning (Сбер) и Gemma 4 26B-A4B — модели «смесь экспертов»: на каждое слово
работает лишь часть параметров (1,8B и 3,8B), поэтому они заметно быстрее обычных моделей
того же качества. Сравнение на реальных записях ещё предстоит — выбор по умолчанию может
поменяться по его итогам.

Каждый запрос к модели сводок измеряется её собственным токенизатором: материал, который
не помещается в контекст, делится на части, а итоговый текст, упёршийся в лимит ответа,
дописывается с места обрыва. Если сводка всё же вышла неполной или прервалась, её можно
продолжить или **сделать заново** с нуля (меню «⋯» → «Сделать сводку заново…»); старая
сводка остаётся, пока новая не готова.

Можно выбрать и свои файлы `.bin` / `.gguf`. Подробности и скорость — в
[руководстве по моделям](docs/models.md#локальная-модель-сводок).

### Запуск из исходников (для разработки)

```bash
git clone https://github.com/Igibaev/samarizator.git && cd samarizator
./start.sh --llm auto
```

Основная ветка — `main`. Нужен [Homebrew](https://brew.sh): `start.sh` ставит uv, FFmpeg,
whisper-cpp и llama.cpp, скачивает модели и открывает окно. Обновиться — закрыть
приложение, `git pull` и снова `./start.sh`. Сборка `.dmg` и выпуск релиза —
[docs/packaging.md](docs/packaging.md).

## Как пользоваться

Окно устроено как приложения Apple: слева список записей с поиском и цветным статусом
(готово, идёт сводка с процентом, проверьте текст, ошибка), справа — выбранная запись.
У записи три вида, переключатель вверху: **Итоговый текст**, **Сводка** и **Расшифровка**.
Справа в панели всегда одна главная кнопка — следующий шаг; всё редкое — в меню **«⋯»**.

1. Перетащите аудио или видео в окно (или **+** вверху списка): MP3, MP4, M4A, WAV, MOV, MKV,
   WebM, FLAC и другие форматы, которые читает FFmpeg. Используется первая аудиодорожка.
2. Нажмите **Распознать**. Аудио остаётся на Mac; ход работы виден на экране с этапами
   и оценкой оставшегося времени. Пока идёт обработка, другие записи можно открывать.
3. Когда текст готов, откроется **Расшифровка**: сверху сказано, сколько реплик стоит
   прослушать. Выберите реплику — внизу появятся «Прослушать», правка текста и повторный
   вариант распознавания.
4. Нажмите **Создать сводку**. Локальная модель разберёт запись блоками, проверит каждый блок
   по расшифровке и соберёт краткую сводку, подробный реестр и **итоговый текст** в выбранном
   формате. По умолчанию сводка укладывается в 10 минут — подробнее ниже.
5. **Итоговый текст** — документ в выбранном формате; формат меняется прямо над текстом.
   **Сводка** — кратко, главное, решения со статусами, задачи с отметкой «сделано» (она
   попадает и в заметку Obsidian), риски, вопросы и полный реестр по ходу встречи.
6. **Открыть в Obsidian** — главная кнопка готовой записи. При первом использовании откройте
   `~/Documents/Samarizator` в Obsidian: «Открыть папку как хранилище». Приложение находит
   хранилище в конфиге Obsidian, поэтому имя папки менять можно; если папка ещё не
   зарегистрирована как хранилище, кнопка скажет об этом и предложит открыть папку в Finder.
   Obsidian устанавливается отдельно; без него заметки доступны в любом Markdown-редакторе.

### Live-запись: микрофон и системный звук

В боковой панели нажмите **«● Live: начать запись»**. На первом запуске macOS запросит
доступ к микрофону для Terminal или Samarizator. Повторное нажатие останавливает запись,
сохраняет WAV в `~/Library/Application Support/Samarizator/recordings`, добавляет его в
список и автоматически запускает локальное распознавание.

В **Настройки → Распознавание речи → Live-запись** выбирается источник: только микрофон,
только системный звук или оба сразу. При «оба» получается один WAV с общей шкалой времени:
канал 1 — микрофон, канал 2 — системный звук. Whisper сводит каналы в моно, поэтому в текст
попадают обе стороны разговора, а разделение по каналам сохраняется для повторной проверки.
Усреднение двух каналов даёт каждому источнику вдвое меньшую амплитуду, чем при одиночной
записи; если микрофон изначально тихий, проверьте **«⋯» → «Качество звука»** и поднимите
громкость входа в системных настройках до начала встречи.

Системный звук берётся **штатным ScreenCaptureKit** — без сторонних драйверов. Маленький
helper из `native/macos-capture` уже собран внутри приложения (при запуске из исходников его
собирает `./start.sh`, нужны Xcode Command Line Tools). Экран не записывается: helper берёт
только звук и отдаёт его приложению потоком.

macOS спросит разрешение **«Запись экрана и системного звука»** — оно отдельное от
микрофонного: в списке включите **Samarizator** (при запуске через `./start.sh` — **Terminal**). Разрешение вступает в силу со следующего запуска, поэтому после выдачи
перезапустите приложение. Текущее состояние helper'а видно в настройках.

Если запись системного звука вышла пустой, запустите диагностику со включённым звуком — она
перебирает варианты настроек захвата и показывает, какой из них доходит до приложения:

```bash
./scripts/diagnose_system_audio.sh
```

Разбор её вывода — в [troubleshooting](docs/troubleshooting.md#системный-звук-пустая-запись).

Запасной путь — **устройство петли** (BlackHole, Loopback или интерфейс с аппаратным
loopback), выбранное выходом звука. Он нужен, если штатный захват запрещён корпоративной
политикой. Учтите: агрегатное устройство в «Настройке Audio-MIDI» само по себе петли не
создаёт, оно лишь объединяет уже существующие устройства.

Если запрещены оба пути, приложение не обходит запрет: остаются микрофон и импорт разрешённой
записи встречи — согласуйте вариант с IT. При выводе звука в динамики микрофон повторно
захватит удалённую речь — эхоподавления пока нет, используйте наушники.

Распознавание идёт **по ходу записи**: как только очередной фрагмент записан целиком, он
уходит в обычный Whisper с теми же границами по паузам и теми же проверками, что и
импортированный файл. После остановки остаётся распознать только хвост, поэтому расшифровка
и сводка готовы почти сразу. Качество от этого не меняется — путь обработки тот же самый.

У каждого пункта сводки есть одна кнопка источника, например **▶ 00:41:22 · 3** — время
первой реплики и сколько реплик подтверждают пункт.
Наведите на него, чтобы увидеть все исходные реплики, а нажмите — чтобы последовательно
прослушать все связанные фрагменты. Близкие интервалы объединяются автоматически.

Каждый блок записи после разбора проверяется по исходной расшифровке. Если модель так и не
вернула ответ в нужном формате даже после повторов и дробления блока, сводка не падает:
проблемная часть сохраняется как явно помеченная выдержка исходных реплик, остальные блоки
и подробная сводка не теряются.

### Что входит в сводку

- Краткий итог и основные темы — без последовательного пересказа всех реплик.
- Решения; задачи с ответственными и сроками, **только если они названы**.
- Риски, разногласия и открытые вопросы.
- Ссылки на конкретные фрагменты расшифровки с таймкодами.
- **Подробный реестр пунктов** из всех исходных блоков до финального сокращения. Это позволяет проверить темы, которые не вошли в короткую сводку.

Запись проходит по всем блокам, а не обрезается под контекст модели.

### Как модель составляет сводку

По умолчанию работает **быстрый алгоритм — конспект** (примерно вдвое быстрее прежнего):

1. **Конспект блоков.** Модель читает пронумерованные реплики `[12] текст` и пишет короткие
   строки: `Решение [12, 14] Бюджет — 17 млн | статус: согласовано`. Несколько блоков
   обрабатываются одновременно.
2. **Проверка блока.** Модель сверяет конспект с расшифровкой, которую уже прочитала, и пишет
   только исправления — обычно одно «ВСЁ ВЕРНО».
3. **Сборка за один заход.** Конспект всей встречи целиком помещается в модель: краткая
   сводка и итоговые статусы решений получаются из одного ответа. Подробная сводка — это сам
   конспект, его собирает программа без модели.
4. **Итоговый текст** по выбранному формату.

**Время на сводку.** По умолчанию сводка укладывается в **10 минут** (Настройки → Сводка →
«Время на сводку»; есть «без ограничения»). Сводка измеряет скорость модели по первым блокам
и планирует остальное: если времени не хватает, сначала пропускает проверку блоков по
расшифровке, потом пишет конспект короче, а итоговому тексту отдаёт то время, что осталось.
Что было сокращено, написано на странице сводки; расшифровка всегда полная. Во время работы
строка состояния показывает «осталось ≈ N мин» по измеренной скорости, а в конце — сколько
занял каждый этап. Если модель пишет медленно (например, 8 токенов в секунду на старом Mac),
сводка всё равно получится — короче и позже, и об этом будет сказано.

Почему так быстрее: читать текст модель может в десятки раз быстрее, чем писать, а прежний
алгоритм переписывал одно и то же содержание три-четыре раза. Если конспект не помещается в
модель (Mac с 8 ГБ или очень длинная запись), сборка автоматически идёт по уровням, как
раньше. Прежний алгоритм остался: **Настройки → Для опытных → Алгоритм сводки →
Классический** — им удобно сравнить результат на той же записи («Сделать сводку заново»).
В журнале обработки видно, сколько занял каждый этап.

В классическом алгоритме синтез объединяет результаты в несколько уровней. Ответы с несуществующими номерами реплик, не в том формате или с признаком обрезания отклоняются. Проверка ID подтверждает существование источника, но не доказывает истинность каждого утверждения: модель всё ещё может ошибиться. Абсолютная полнота и безошибочность автоматической сводки не гарантируются.

## Более точная модель распознавания

По умолчанию для русской речи предлагается **Podlodka Turbo**. Для максимальной точности на
мощном Mac (например, **M4 Pro с 48 ГБ**) выберите полную `large-v3`: **Настройки →
Основное → «Распознавание речи» → «Сменить…» → «Скачать модель…»** (около 2,9 ГиБ;
`large-v3-turbo` — почти так же точно и в несколько раз быстрее). Там же, в **«Для
опытных»**, — профиль **«Применить профиль M4 Pro · 48 ГБ»**: больше памяти и потоков,
поиск пауз на границах фрагментов.

Затем импортируйте файл или выберите **«⋯» → «Распознать заново»** у существующей записи.
Продолжение старой расшифровки намеренно использует сохранённую для неё модель; новый проход
создаёт отдельную запись, поэтому результаты можно сравнить и прежний текст не потеряется.
Из исходников то же самое: `./start.sh --quality --large-v3`.

`large-v3` не гарантирует лучший результат на каждой записи: микрофон, шум, музыка и
незнакомые имена тоже влияют на точность. Варианты и компромиссы — в
[руководстве по моделям](docs/models.md), как устроено распознавание и проверка спорных
мест — в [качестве распознавания](docs/quality.md).

## Вопросы по записи

Кнопка **«Спросить»** открывает справа чат. Вверху переключатель — откуда брать ответ:

**По сводке** — «Какие решения приняли?», «Что должна сделать Ирина?», «Что осталось
нерешённым?»:

- модель получает лишь пронумерованные пункты сводки (кратко, итоговые статусы решений и
  задач, реестр по ходу встречи) — не расшифровку, не интернет и не другие записи;
- каждое утверждение в ответе ссылается на номер пункта.

**По расшифровке** — для деталей, которых нет в сводке: «Какие суммы назывались?», «Что
говорили о сроках?», «Как ответили на вопрос про поставщика?»:

- модель читает саму расшифровку: пронумерованные реплики со временем; ответ ссылается на
  номера реплик, соседние реплики собираются в один фрагмент;
- расшифровка стоит в начале запроса, поэтому модель читает её **один раз**: первый вопрос
  ждёт этого чтения (на двухчасовой встрече — до минуты), следующие отвечаются за секунды;
- окно модели для этого увеличивается, насколько позволяет память Mac (до 64 тыс. токенов).
  Если запись всё равно не помещается, модель получает реплики со словами из вопроса и
  их соседей — под ответом будет пометка об этом;
- говорящие в расшифровке не подписаны: «что сказал Иванов» сработает, только если имя
  прозвучало в самих репликах;
- спрашивать по расшифровке можно и до того, как создана сводка.

В обоих режимах под ответом кнопки **▶ время** источников: наведение показывает реплики,
клик проигрывает их. Приложение само проверяет ответ: если он не опирается на существующие
пункты или реплики (вопрос не о встрече, общие знания, попытка «снять ограничения»),
вместо него показывается «об этом нет». История разговора хранится у записи; «Очистить» —
начать заново.

Чат использует ту же локальную модель, что и сводки: первый вопрос ждёт её загрузки,
дальше ответы быстрые. Модель выгружается через 10 минут тишины и перед созданием сводки.

## Настройка итогового текста

- **Настройки → Основное → «Что важно в ваших записях»** — свободный текст, который
  получает модель на каждом шаге: для кого сводка, что важно, как называются ваши термины.
  Например: «Сводка для отдела продаж. Выделяй цены, сроки поставки и возражения клиентов».
- **Итоговый текст** — готовые шаблоны: протокол встречи, резюме для руководителя,
  конспект лекции, интервью. Выбирается в настройках или прямо над готовым текстом.
- **Настройки → «Шаблон итогового текста»** — редактируемое описание документа: разделы,
  порядок, таблицы, объём, стиль. Пишется обычными словами, модель ему следует.

Правила точности встроены и не отключаются: только факты из записи, «предложено» не
выдаётся за «решили», ответственные и сроки — только названные. Сменили шаблон у готовой
записи — выберите другой формат прямо над итоговым текстом: проверенный реестр пунктов
переиспользуется, запись заново не разбирается. Итоговый текст можно скопировать в
Markdown, он же открывает заметку встречи в Obsidian.

## Память и длительные записи

По умолчанию бюджет памяти распознавания — **4 ГиБ** (больше, если этого требует модель),
4 потока CPU, фрагменты по 120 секунд. Whisper и модель сводок работают на **GPU (Metal)**:
это в разы быстрее и холоднее, чем на процессоре. Контроль памяти учитывает и память GPU —
на macOS он читает физический объём процесса, как «Память» в Мониторе системы. Выключить GPU
для распознавания можно в **Настройки → Для опытных → «Распознавание на GPU»**, но обычно это
не нужно. Если Mac греется, включено **«Беречь Mac от перегрева»**: при сильном нагреве
обработка делает паузы.

- Одна задача за раз. FFmpeg извлекает только очередной фрагмент; Whisper не загружает всё медиа.
- Whisper и FFmpeg запускаются отдельными контролируемыми процессами.
- Контроль суммарной памяти приложения и дочерних процессов каждые 100 мс.
- Защитная остановка при **90% выбранного бюджета**; запас предназначен для колебаний между проверками.
- Фрагменты и сводки блоков сохраняются транзакционно в SQLite. После остановки можно продолжить. Текущий незавершённый фрагмент выполняется повторно.
- При повторном запуске проверяется SHA-256 исходного файла: изменённое медиа нельзя незаметно смешать с прежней расшифровкой.

**Это не жёсткая квота оперативной памяти на уровне macOS.** Быстрое выделение памяти может кратковременно превысить порог до следующей проверки. Подсчёт не учитывает системный файловый кеш; внешние приложения, Homebrew и установка моделей не входят в бюджет. Режим гарантированного жёсткого потолка потребовал бы отдельной VM/контейнера и не входит в эту версию.

На границах фрагментов используется перекрытие 2 секунды. Пограничные реплики помечаются для проверки: возможны повторы или различия распознавания на стыке. Это не гарантия пословного выравнивания.

## База знаний

```text
Samarizator/
  Meetings/2026-09-10 1455 Планёрка отдела продаж.md     # сводка, решения, задачи
  Transcripts/2026-09-10 1455 Планёрка отдела продаж.md  # полная расшифровка
  Topics/внедрение QBS Flow.md                           # только повторяющиеся темы
  Встречи — индекс.md                                    # запросы по всем встречам
```

Имя заметки — дата, время и название встречи: папка сортируется хронологически, а идентификаторы остаются в свойствах. У каждой встречи есть свойства `date`, `duration`, `topics`, `meeting_id`, поэтому списки собираются запросом, а не руками. Индексная заметка создаётся один раз и дальше принадлежит вам: в ней готовые запросы Dataview и варианты для встроенного поиска. Заголовки чистятся от UUID и подчёркиваний, которые тянутся из имён исходных файлов.

Заметка темы заводится, только когда тема встретилась **минимум в двух встречах**, и её имя не содержит хеша — поэтому одинаковые темы сливаются в один узел. Разовые формулировки остаются в свойстве `topics` и не засоряют граф. Синонимы не объединяются магически — их можно свести вручную в Obsidian.

Ссылки на расшифровку ставятся только на реплики, процитированные в сводке, поэтому панель обратных ссылок остаётся читаемой. Сами расшифровки удобно убрать из графа: Настройки графа → Фильтры → `-path:Transcripts`. Никакой автоматической загрузки в Obsidian Sync нет.

Заметки, экспортированные до этой схемы, остаются как есть: приложение их не переименовывает и не удаляет.

Экспорт обновляется автоматически после успешной сводки. Если заметка или расшифровка были изменены вручную, следующая выгрузка создаст новую пару файлов и сохранит старую. Изменение расшифровки в приложении сбрасывает сводку: её нужно пересоздать. Старые экспортированные версии остаются в хранилище для истории.

## Обезличивание для внешних нейросетей

Вкладка **«Обезличивание»** — копия записи без персональных данных, чтобы отправить её в
облачную нейросеть (например, для сводки «на уровень выше»). Всё считается на Mac.

- **Что скрывается:** люди (имя, фамилия, отчество — во всех падежах одной меткой:
  «Ирина», «Ирине», «Ириной Петровой» → `[Человек 1]`), места, организации (в том числе
  «ООО «…»»), телефоны, почта, ссылки, банковские карты, паспорта, СНИЛС и любые длинные
  номера (ИНН, ИИН, договоры, счета). Имена и места находит словарь русской морфологии
  pymorphy3, номера — шаблоны.
- **Таблица слева** фиксирует каждую замену: метка, что скрыто (во всех встреченных
  формах), тип и сколько раз. Галочкой можно оставить данные как есть, «Скрыть своё
  слово…» добавляет имя клиента или название проекта — тоже во всех падежах. Выбор
  сохраняется для записи.
- **Справа** — обезличенная расшифровка, итоговый текст или сводка с подсвеченными
  метками: «Скопировать» или «Сохранить .md…». Метки одинаковы во всех трёх текстах.
  Название записи (оно из имени файла и может содержать имя) в файл не попадает.
- **«Вернуть данные в ответ ИИ…»**: вставьте ответ внешней нейросети — метки заменятся на
  настоящие имена и номера из таблицы. Таблица соответствий никуда не выгружается.
- **«Сохранить в запись»** в том же окне: ответ с настоящими данными становится **итоговым
  текстом записи** с пометкой «Ответ внешней нейросети» и попадает в заметку Obsidian. Если
  сводки модели у записи ещё не было, это и есть её сводка: так можно сделать сводку целиком
  во внешней нейросети. Если сводка модели есть, заменяется только итоговый текст — краткая
  и подробная сводка с решениями и задачами остаются, а текст модели можно написать снова
  («⋯» → «Пересоздать итоговый текст»). «Создать сводку» у записи с одним ответом внешней
  нейросети заменяет его сводкой модели.

Автоматический поиск находит не всё (например, имена латиницей или прозвища): перед
отправкой просмотрите текст и добавьте недостающее своими словами.

**Расшифровка в Markdown** — меню «⋯» → «Экспорт расшифровки в Markdown…»: абзацы с
таймкодами, сомнительные места помечены «(проверить по записи)».

## Данные и приватность

- Медиа: исходный файл не копируется и не удаляется.
- Состояние, расшифровки, настройки, модели: `~/Library/Application Support/Samarizator`.
- Заметки: `~/Documents/Samarizator` либо выбранная папка.
- SQLite и Markdown не зашифрованы приложением. При необходимости используйте FileVault и корпоративные правила хранения.
- Нет телеметрии, облачного распознавания и облачных сводок. Внешние LLM-сервисы не подключаются: сводку делает локальная модель через `llama-server`, который слушает только `127.0.0.1` с одноразовым ключом и живёт лишь на время задачи.
- Ни аудио, ни текст не покидают Mac. Сеть нужна только для загрузки весов моделей с Hugging Face — один раз.
- Временные WAV и технические логи удаляются после обработки, а оставшиеся после аварийного выхода — при следующем запуске.

Репозиторий содержит только приложение, тесты и документацию. В нём нет ключей, записей, моделей или корпоративных материалов.

## Разработка и проверка

```bash
uv sync --frozen --extra dev
uv run --frozen --extra dev pytest -q
uv run --frozen --extra dev ruff check src tests
```

Для Linux headless задайте `QT_QPA_PLATFORM=offscreen`. Основная ветка — `main`; изменения
приходят через pull request, тесты и Ruff запускаются локально до него. GitHub Actions
собирает `.dmg` и выпускает релизы ([docs/packaging.md](docs/packaging.md)), перед сборкой
тоже прогоняя тесты. `scripts/smoke_audio.py` — ручной прогон на Mac с настоящими FFmpeg и
Whisper ([docs/quality.md](docs/quality.md#ручная-проверка-на-mac)). Модель сводок в тестах
заменена HTTP-транспортом и поддельным `llama-server` с теми же флагами и эндпоинтами —
модель скачивать не нужно.
