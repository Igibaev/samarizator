# Samarizator

**Обновление для M4 Pro / 48 ГБ:** `git pull --ff-only`, затем `./start.sh --quality`.
Ваши модели и корпоративный API сохраняются. Новый профиль добавляет локальный VAD,
границы по паузам, словарь терминов, диагностику и отдельные краткую/подробную сводки.
[Параметры, сравнение моделей и ограничения](docs/quality.md).
Для нового ASR импортируйте запись заново; для новых сводок нажмите «Создать сводку» ещё раз.


Десктопное приложение для macOS: превращает аудио и видео в содержательные заметки с решениями, задачами и таймкодами. Распознавание происходит локально через **Whisper.cpp**, сводки — через **любой OpenAI-совместимый API** (OpenAI, OpenRouter, Groq, локальная модель по API). База знаний — папка Markdown для **Obsidian с графом связей**.

## Запуск на Mac

Нужен macOS 13+ и [Homebrew](https://brew.sh). Готовые пакеты Homebrew доступны не на всех старых версиях macOS; для максимально простой установки используйте поддерживаемую Homebrew версию системы. Поддерживаются Apple Silicon и Intel; скорость зависит от процессора.

```bash
git clone https://github.com/Igibaev/samarizator.git && cd samarizator
./start.sh
```

Первый запуск устанавливает uv, FFmpeg, Whisper.cpp и Python-зависимости, скачивает модели и открывает окно. Нужен интернет для установки; модели занимают несколько сотен МБ, зависимости — дополнительное место. Последующие запуски используют готовое окружение и модели. Если Homebrew ещё нет, установите его по инструкции на brew.sh и повторите команду.

### Ошибка SSL-сертификата при установке

Если `./start.sh` падает с ошибкой проверки SSL-сертификата (часто бывает за корпоративным прокси/MITM-сертификатом), соберите системные сертификаты в один файл и повторите установку с ним:

```bash
security find-certificate -a -p /System/Library/Keychains/SystemRootCertificates.keychain > /tmp/all-certs.pem
security find-certificate -a -p /Library/Keychains/System.keychain >> /tmp/all-certs.pem
rm -rf .venv
SSL_CERT_FILE=/tmp/all-certs.pem uv sync
```

Чтобы зафиксировать это на будущее (без повторного экспорта переменной каждый раз), создайте в корне проекта файл `uv.toml` рядом с `pyproject.toml`:

```toml
allow-insecure-host = ["pypi.org", "files.pythonhosted.org"]
```

Это отключает проверку TLS-сертификата именно для этих двух хостов при установке пакетов через uv — используйте только если понимаете, почему сертификат не проходит проверку (например, корпоративный прокси с собственным CA).

В **Настройки → Облачная модель · сводки** один раз укажите:

1. **Провайдер** — выпадающий список подставит base URL для OpenAI, OpenRouter, Groq, DeepSeek, Together, а также локальных Ollama и LM Studio. Любой другой совместимый адрес можно вписать вручную.
2. **Base URL** — корень API, например `https://openrouter.ai/api/v1`. Путь `/chat/completions` приложение дописывает само; вставленный целиком endpoint тоже принимается.
3. **Название модели**, доступной вашему аккаунту у этого провайдера, например `openai/gpt-4o-mini`.
4. **API-ключ** — сохраняется в macOS Keychain, не в Git и не в настройках. Уходит заголовком `Authorization: Bearer`.

Подходит любой OpenAI-совместимый Chat Completions API. Ключ по умолчанию не предзаполнен, публичной модели и запасного облачного сервиса в приложении нет. HTTPS обязателен для всех адресов, кроме локальных на `localhost` — там разрешён `http`, чтобы работали Ollama и LM Studio. OAuth/SSO-only веб-чат без API напрямую не поддерживается.

## Как пользоваться

1. Добавьте локальный аудио- или видеофайл: MP3, MP4, M4A, WAV, MOV, MKV, WebM, FLAC и другие форматы, которые читает FFmpeg. Используется первая аудиодорожка.
2. Нажмите **Распознать / продолжить**. Аудио остаётся на Mac.
3. Проверьте отмеченные реплики и исправьте ошибки текста.
4. Нажмите **Создать сводку**. Только на этом этапе текст отправляется на выбранный API модели.
5. Откройте результат через **Открыть в Obsidian**. При первом использовании откройте `~/Documents/Samarizator` в Obsidian: «Открыть папку как хранилище». Приложение находит хранилище в конфиге Obsidian, поэтому имя папки менять можно; если папка ещё не зарегистрирована как хранилище, кнопка скажет об этом и предложит открыть папку в Finder. Obsidian устанавливается отдельно; без него заметки доступны в любом Markdown-редакторе.

### Live-запись: микрофон и системный звук

В боковой панели нажмите **«● Live: начать запись»**. На первом запуске macOS запросит
доступ к микрофону для Terminal или Samarizator. Повторное нажатие останавливает запись,
сохраняет WAV в `~/Library/Application Support/Samarizator/recordings`, добавляет его в
список и автоматически запускает локальное распознавание.

В **Настройки → Распознавание речи → Live-запись** выбирается источник: только микрофон,
только системный звук или оба сразу. При «оба» получается один WAV с общей шкалой времени:
канал 1 — микрофон, канал 2 — системный звук. Whisper сводит каналы в моно, поэтому в текст
попадают обе стороны разговора, а разделение по каналам сохраняется для повторной проверки.
Усреднение двух каналов даёт каждому источнику вдвое меньшую амплитуду, чем при одиночной
записи; если микрофон изначально тихий, проверьте вкладку **«Качество записи»** и поднимите
громкость входа в системных настройках до начала встречи.

Системный звук берётся **штатным ScreenCaptureKit** — без сторонних драйверов. `./start.sh`
собирает для этого маленький helper из `native/macos-capture` (нужны Xcode Command Line Tools:
`xcode-select --install`). Экран не записывается: helper берёт только звук и отдаёт его
приложению потоком.

macOS спросит разрешение **«Запись экрана и системного звука»** — оно отдельное от
микрофонного и выдаётся приложению-хозяину: при запуске через `./start.sh` в списке нужно
включить **Terminal**. Разрешение вступает в силу со следующего запуска, поэтому после выдачи
перезапустите приложение. Текущее состояние helper'а видно в настройках.

Если запись системного звука вышла пустой, запустите диагностику со включённым звуком — она
перебирает варианты настроек захвата и показывает, какой из них доходит до приложения:

```bash
./scripts/diagnose_system_audio.sh
```

Разбор её вывода — в [troubleshooting](docs/troubleshooting.md#системный-звук-пустая-запись).

Запасной путь — **устройство петли** (BlackHole, Loopback или интерфейс с аппаратным
loopback), выбранное выходом звука. Он нужен, если штатный захват запрещён корпоративной
политикой. Учтите: агрегатное устройство в «Настройке Audio-MIDI» само по себе петли не
создаёт, оно лишь объединяет уже существующие устройства.

Если запрещены оба пути, приложение не обходит запрет: остаются микрофон и импорт разрешённой
записи встречи — согласуйте вариант с IT. При выводе звука в динамики микрофон повторно
захватит удалённую речь — эхоподавления пока нет, используйте наушники.

Распознавание идёт **по ходу записи**: как только очередной фрагмент записан целиком, он
уходит в обычный Whisper с теми же границами по паузам и теми же проверками, что и
импортированный файл. После остановки остаётся распознать только хвост, поэтому расшифровка
и сводка готовы почти сразу. Качество от этого не меняется — путь обработки тот же самый.

У каждого тезиса в сводке есть один компактный значок **▶** без россыпи таймкодов.
Наведите на него, чтобы увидеть все исходные реплики, а нажмите — чтобы последовательно
прослушать все связанные фрагменты. Близкие интервалы объединяются автоматически.

В версии «Сводки 2.6» подробные блоки дополнительно проверяются по исходной расшифровке.
Приоритет — полнота и точность; запросов модели стало больше.
[Как устроена проверка и её ограничения](docs/summary-source-review.md).

Если корпоративная модель не возвращает корректный JSON даже после повторов и дробления,
вся операция больше не падает: проблемная часть сохраняется как явно помеченная выдержка
исходных реплик. Остальные блоки и подробная сводка не теряются.

### Что входит в сводку

- Краткий итог и основные темы — без последовательного пересказа всех реплик.
- Решения; задачи с ответственными и сроками, **только если они названы**.
- Риски, разногласия и открытые вопросы.
- Ссылки на конкретные фрагменты расшифровки с таймкодами.
- **Подробный реестр пунктов** из всех исходных блоков до финального сокращения. Это позволяет проверить темы, которые не вошли в короткую сводку.

Запись проходит по всем блокам, а не обрезается под контекст модели. Синтез объединяет результаты в несколько уровней. Ответы с несуществующими ID фрагментов, повреждённым JSON или признаком обрезания отклоняются. Проверка ID подтверждает существование источника, но не доказывает истинность каждого утверждения: модель всё ещё может ошибиться. Абсолютная полнота и безошибочность автоматической сводки не гарантируются.

## Более точная модель

По умолчанию используется лёгкая мультиязычная Whisper `small-q5_1`, чтобы приложение
запускалось на разных Mac. Для **M4 Pro с 48 ГБ RAM** рекомендуемый режим максимального
качества — полная мультиязычная `large-v3`:

```bash
./start.sh --quality --large-v3
```

При первом таком запуске приложение скачает `ggml-large-v3.bin` (около 2,9 ГиБ), выберет
его для распознавания, включит VAD и выставит бюджет 16 ГиБ. Корпоративный API, ключ,
папка Obsidian и остальные пользовательские настройки сохранятся. После завершения
скачивания последующие запуски обычные:

```bash
./start.sh
```

Проверьте в **Настройки → Распознавание речи · локально**, что модель указывает на
`~/Library/Application Support/Samarizator/models/ggml-large-v3.bin`, язык — `ru`,
beam size — `5`, VAD включён, бюджет памяти — `16 ГиБ`. Затем импортируйте файл или
нажмите **«Распознать заново»** у существующей записи. Продолжение старой расшифровки
намеренно использует сохранённую для неё модель; новый проход создаёт отдельную запись,
поэтому результаты можно сравнить и прежний текст не потеряется.

`large-v3` не гарантирует лучший результат на абсолютно каждой записи: микрофон, шум,
перегрузка, музыка и незнакомые имена тоже влияют на точность. Для менее мощного Mac или
когда важнее скорость доступны `large-v3-turbo` и квантованные варианты; их установка,
размеры и компромиссы описаны в [руководстве по моделям](docs/models.md).

### Более сильная корпоративная модель для сводок

Модель сводок не скачивается приложением: в **Настройки → Облачная модель · сводки**
указывается точное имя модели, разрешённой в корпоративном OpenAI-совместимом API.
Выбирайте полноценную instruction-модель верхнего уровня из корпоративного каталога,
которая хорошо работает с русским языком, стабильно возвращает JSON и имеет контекст
не менее 32k токенов. Для подробной сводки начните с `12000` символов на запрос и
`6000` токенов ответа; если шлюз не разрешает такой вывод, верните лимит к `3000`.
Аудио при этом никуда не отправляется — корпоративная модель получает только текст.

## Память и длительные записи

По умолчанию: **4 ГиБ**, 4 потока CPU, фрагменты по 120 секунд, квантованная мультиязычная `small-q5_1`. Whisper по умолчанию запускается с `-ng`: GPU/Metal выключен, чтобы не скрывать потребление в общей GPU-памяти. Это медленнее GPU и сильнее греет ноутбук, потому что вся работа ложится на CPU.

Галочка **Настройки → Распознавание речи · локально → «Ускорение»** снимает `-ng` и переносит вычисления на Metal. Качество распознавания не меняется — модель и веса те же, отличается только бэкенд. Взамен память Metal не попадает в подсчёт RSS, поэтому бюджет памяти перестаёт быть точной оценкой на длинных записях. Если ноутбук греется, это самый действенный переключатель; следующий по эффективности — уменьшить число потоков CPU.

- Одна задача за раз. FFmpeg извлекает только очередной фрагмент; Whisper не загружает всё медиа.
- Whisper и FFmpeg запускаются отдельными контролируемыми процессами.
- Контроль суммарного RSS приложения и дочерних процессов каждые 100 мс.
- Защитная остановка при **90% выбранного бюджета**; запас предназначен для колебаний между проверками.
- Фрагменты и сводки блоков сохраняются транзакционно в SQLite. После остановки можно продолжить. Текущий незавершённый фрагмент выполняется повторно.
- При повторном запуске проверяется SHA-256 исходного файла: изменённое медиа нельзя незаметно смешать с прежней расшифровкой.

**Это не жёсткая квота оперативной памяти на уровне macOS.** Быстрое выделение памяти может кратковременно превысить порог до следующей проверки. RSS не учитывает весь системный файловый кеш; внешние приложения, Homebrew и установка моделей не входят в бюджет. Режим гарантированного жёсткого потолка потребовал бы отдельной VM/контейнера и не входит в эту версию.

На границах фрагментов используется перекрытие 2 секунды. Пограничные реплики помечаются для проверки: возможны повторы или различия распознавания на стыке. Это не гарантия пословного выравнивания.

## База знаний

```text
Samarizator/
  Meetings/2026-09-10 1455 Планёрка отдела продаж.md     # сводка, решения, задачи
  Transcripts/2026-09-10 1455 Планёрка отдела продаж.md  # полная расшифровка
  Topics/внедрение QBS Flow.md                           # только повторяющиеся темы
  Встречи — индекс.md                                    # запросы по всем встречам
```

Имя заметки — дата, время и название встречи: папка сортируется хронологически, а идентификаторы остаются в свойствах. У каждой встречи есть свойства `date`, `duration`, `topics`, `meeting_id`, поэтому списки собираются запросом, а не руками. Индексная заметка создаётся один раз и дальше принадлежит вам: в ней готовые запросы Dataview и варианты для встроенного поиска. Заголовки чистятся от UUID и подчёркиваний, которые тянутся из имён исходных файлов.

Заметка темы заводится, только когда тема встретилась **минимум в двух встречах**, и её имя не содержит хеша — поэтому одинаковые темы сливаются в один узел. Разовые формулировки остаются в свойстве `topics` и не засоряют граф. Синонимы не объединяются магически — их можно свести вручную в Obsidian.

Ссылки на расшифровку ставятся только на реплики, процитированные в сводке, поэтому панель обратных ссылок остаётся читаемой. Сами расшифровки удобно убрать из графа: Настройки графа → Фильтры → `-path:Transcripts`. Никакой автоматической загрузки в Obsidian Sync нет.

Заметки, экспортированные до этой схемы, остаются как есть: приложение их не переименовывает и не удаляет.

Экспорт обновляется автоматически после успешной сводки. Если заметка или расшифровка были изменены вручную, следующая выгрузка создаст новую пару файлов и сохранит старую. Изменение расшифровки в приложении сбрасывает сводку: её нужно пересоздать. Старые экспортированные версии остаются в хранилище для истории.

## ИИ-компаньон — персонаж в вырезе

В `focus-companion/` живёт отдельное macOS-приложение: персонаж в вырезе MacBook с тремя слотами под дела, записью и сводкой прямо из вырeза (см. `focus-companion/README.md`). После каждой сводки Samarizator передаёт ему поручения со статусом «согласовано»: персонаж говорит об этом одной репликой, а кнопка «В фокус» на его странице «Записи» кладёт в слот короткую формулировку вместо абзаца из саммари. Сам он в слоты ничего не добавляет. Передача — файл `inbox/<id встречи>.json` в папке персонажа `~/Library/Application Support/dev.samarizator.focuscompanion/`; он пишется, только если эта папка уже существует, то есть персонаж хоть раз запускался. Реплику сочиняет та же облачная модель одним дополнительным коротким запросом; если модель недоступна или отвечает не в характере, подставляется запасная реплика, а дела доходят с исходной формулировкой. Выключается в **Настройки → Облачная модель · сводки → «Передавать согласованные дела ИИ-компаньону»**. Кто такой персонаж и как говорит — `docs/focus-companion/CHARACTER-BIBLE.md`.

### Дневник: заметка дня и «Поручения»

После каждой сводки и каждого изменения в слотах компаньона в папке заметок обновляются две заметки:

- `Дни/2026-09-23.md` — встречи дня со ссылками и согласованными поручениями; что было в фокусе, что сделано, что отпущено (сгорело или убрано). Правится только блок между метками `<!-- samarizator:… -->`; ваш текст выше и ниже, например в разделе «Мои заметки», не трогается. Прошедшие дни хранят свою запись фокуса и не пересобираются задним числом.
- `Поручения.md` — все согласованные поручения со всех встреч: «В фокусе сейчас», «Ждут», «Сделано». Выполненным считается поручение, отмеченное галочкой в заметке встречи или кружком в компаньоне. Эта заметка пересобирается целиком — правки в ней не сохранятся.

Запросов к модели дневник не делает. Выключается в **Настройки → Облачная модель · сводки → «Дневник»**. Вручную: `.venv/bin/python -m samarizator.companion journal`. Проверка всей связки на Mac — [чек-лист](docs/focus-companion/CHECKLIST.md).

## Данные и приватность

- Медиа: исходный файл не копируется и не удаляется.
- Состояние, расшифровки, настройки, модели: `~/Library/Application Support/Samarizator`.
- Заметки: `~/Documents/Samarizator` либо выбранная папка.
- Секрет: macOS Keychain; для автоматизации можно задать `SAMARIZATOR_API_KEY`.
- ИИ-компаньон: согласованные дела из сводки (текст пунктов, ответственный, срок) и путь к заметке — в `~/Library/Application Support/dev.samarizator.focuscompanion/inbox/`, только если персонаж установлен; в API сводок при этом уходит один дополнительный запрос с текстом этих пунктов.
- Дневник: заметки `Дни/` и `Поручения.md` в папке заметок; источник — база Samarizator и `tasks.json` компаньона, наружу ничего не уходит.
- SQLite и Markdown не зашифрованы приложением. При необходимости используйте FileVault и корпоративные правила хранения.
- Нет телеметрии, облачного ASR, публичного fallback, автоматических редиректов или чтения системных HTTP-прокси. VPN поддерживается на уровне сети ОС. Если нужен обязательный HTTP-прокси или нестандартный заголовок авторизации, потребуется адаптация клиента.
- Аудио не отправляется ни в API сводок, ни в модельные хостинги: распознавание всегда локальное. Загрузки моделей обращаются к Hugging Face/GitHub только за весами.
- Временные WAV и технические логи удаляются после обработки, а оставшиеся после аварийного выхода — при следующем запуске.

Репозиторий содержит только приложение, тесты и документацию. В нём нет ключей, записей, моделей или корпоративных материалов.

## Разработка и проверка

```bash
uv sync --frozen --extra dev
uv run --frozen --extra dev pytest -q
uv run --frozen --extra dev ruff check src tests
```

Для Linux headless задайте `QT_QPA_PLATFORM=offscreen`. GitHub Actions в проекте не используется — тесты и Ruff запускаются локально перед коммитом/PR. Отдельный `scripts/smoke_audio.py` — ручной smoke-test на Mac с настоящими FFmpeg и Whisper, см. `docs/quality.md`. API сводок в тестах заменён контролируемым HTTP-транспортом — реальные ключи не нужны.
