# Проверка передачи контекста: версия 2.5

Актуальная реализация: [сверка по источнику](summary-source-review.md). Пользователь сообщил,
что промпты 2.4 ухудшили результат; приведённый ниже пример остаётся материалом для сравнения,
а не свидетельством улучшения. В 2.5 сняты ограничения одного предложения и 300 символов,
добавлены исходный контекст на границах и отдельная проверка подробных блоков.
Вызовов модели стало больше. Правила передачи текста и выбранная корпоративная модель сохранены.

## Контрольный текст (синтетический пример, не реальная запись)

1. Готовим отчёт по задержкам TOS. Сейчас графики в Grafana расходятся с выгрузкой событий.
2. Grafana агрегирует интервалы, а нам нужны отдельные операции с точным временем.
3. Можно брать данные из Grafana для отчёта. Это предложение, пока не решили.
4. Нет, договорились: Grafana только для сверки. Основные данные берём из событий TOS.
5. Сырые события тоже не готовы: у части операций нет времени завершения.
6. Султан проверит полноту событий к пятнице. Только после проверки решим, годятся ли они для отчёта.
7. Предлагаю обновлять каждые пять минут. Пока это гипотеза, надо проверить нагрузку.
8. Срок проверки переносим с пятницы на понедельник, потому что доступ дадут только в пятницу.
9. Это перенос проверки полноты, не обещание запустить весь отчёт в понедельник.
10. Допустимую долю пропусков ещё не согласовали. Критерий качества остаётся открытым.

При проверке пайплайна присвоить строкам реальные ID сегментов. Для проверки промптов напрямую
в корпоративном API использовать формат {id, start, uncertain, text} и SYSTEM + MAP_PROMPT из summary_prompts.py; строки передать в source.segments,
source.before/after — пустые массивы для этого отдельного примера.
Сравнивать старые и новые инструкции на одинаковой модели и настройках, минимум три запуска.

## Что обязательно должно быть в хорошем результате

- Контекст: отчёт по задержкам TOS, расхождение агрегатов Grafana с событиями.
- Решение: Grafana используется для сверки; основной источник — события TOS, пригодность
  которых ещё нужно проверить. Не утверждать, что полноценный отчёт уже готов.
- Задача: Султан проверяет полноту; последний срок — понедельник, причина переноса — доступ.
- Пять минут — предложенная частота, не согласованный регламент.
- Риск: отсутствуют времена завершения; открытый вопрос: допустимая доля пропусков.
- В подробном результате сохранена история переноса. Итоговый раздел не содержит две
  независимые действующие задачи на пятницу и понедельник.
- Источники каждого тезиса прямо подтверждают его целиком. Неизвестная календарная дата
  понедельника не выдумывается. Нет фиктивных ответственных или новых решений.

Оценка вручную: наличие пяти смысловых пунктов выше, отсутствие придуманных фактов,
правильность статусов/сроков и источников, понятность без расшифровки. Отдельно измерить
общее время, количество запросов/повторов, входные и выходные токены, если API их возвращает.
Повторить на своей длинной записи, где пересмотр происходит в другом блоке: промпт не может
восстановить контекст, который не попал в его вход. Стыки блоков требуют отдельного сравнения.

Автотесты проверяют работу пайплайна с подменой модели. Реальное улучшение качества и скорости
корпоративного API в среде разработки не измерено: нужны его ответы и контрольная расшифровка.
