# Передача проекта следующей модели

Состояние на 10 сентября 2026 года. Это передача незавершённой доработки, а не отчёт о полностью готовом релизе.

## 1. Задача и ограничения пользователя

Пользователь работает на **Mac M4 Pro, 48 ГБ RAM**. Нужен desktop-проект для аудио/видео:

- Максимально качественная локальная транскрибация Whisper и разделение собеседников.
- Содержательная суммаризация корпоративной моделью: отдельно подробная и короткая тезисная.
- Контролируемое потребление памяти, без загрузки всей записи и нескольких тяжёлых моделей одновременно для ASR.
- База знаний в Obsidian с темами, источниками и таймкодами.
- Простой запуск в одну-две команды.
- В перспективе live-транскрибация и сводки, микрофон и системный звук раздельно.

Пользователь уже самостоятельно улучшил проект и поменял модели. Нельзя потерять его изменения или молча заменить выбранную модель/API.
Точное имя его текущей ASR-модели и размеченные образцы записей не предоставлены.
Корпоративный endpoint/ключ не предоставлены для проверки реальных ответов.
Пользователь просил обход корпоративного ограничения системного звука: обход не реализовывать;
предложенный путь — штатный ScreenCaptureKit и разрешённая IT конфигурация.

Работать по приоритетам: качество файлового ASR → две сводки → проверка качества и второй проход → live.
Не переписывать проект с нуля. Не заявлять измеренный прирост точности без сравнения на реальных примерах.

## 3. Что реализовано

### Профиль M4 Pro / 48 ГБ и установка

`Settings.quality_profile()` в `src/samarizator/config.py`:

- Бюджет 16 ГиБ, 8 потоков CPU, целевой фрагмент 90 секунд, beam size 5.
- Поиск границ по паузам и локальный VAD включены.
- GPU/Metal выключен по умолчанию: RSS не учитывает всю память Metal.
- Сохраняются выбранная модель Whisper, язык и настройки корпоративного API.
- Новые параметры имеют совместимые значения по умолчанию для старых сохранённых записей.

`./start.sh --quality` скачивает Silero VAD v6.2.0 и применяет профиль.
`./start.sh --quality --large-v3` дополнительно скачивает и выбирает полную multilingual large-v3 (~3.1 GB).
Large-v3 — только дополнительный кандидат для сравнения, не гарантированное улучшение.
Обычный последующий запуск: `./start.sh`.
При `SAMARIZATOR_STRICT=1` CLI-установщик не включает VAD и переводит диаризацию в ручной режим.

В `start.sh` добавлены `UV_SYSTEM_CERTS` и `UV_NATIVE_TLS`: uv использует системные сертификаты,
проверка TLS не отключается. Python truststore уже был в пользовательской версии и сохранён.
Ранее у пользователя возникал `UnknownIssuer` при установке cffi через uv.
Доверенный корпоративный root CA должен быть установлен штатно; это не обход сертификатов.

### Файловая транскрибация

Новый `src/samarizator/audio_quality.py`:

- Поточное чтение mono PCM16 16 kHz по 20 мс, без большого массива всей записи.
- Поиск тихой паузы около намеченной границы: окно ±6 секунд, уровень примерно −38 dBFS,
  длительность паузы от 350 мс, небольшой запас внутри паузы.
- Эта энергетическая эвристика **только выбирает место разреза**, ничего не вырезает.
- Границы привязаны к исходной временной сетке, чтобы сдвиги не накапливались.
- Диагностика RMS, полностью нулевого сигнала и возможного отсечения пиков.
  Это не измерение SNR, не оценка точности ASR и не полная диагностика исходных каналов.

Изменения `media.py` и `worker.py`:

- Подключён локальный VAD whisper.cpp: threshold 0.4, минимальная речь 150 мс,
  минимальная пауза 500 мс, padding 250 мс. Эти настройки ещё не откалиброваны на записях пользователя.
- Словарь терминов до 800 символов передаётся как `--prompt`: имена, аббревиатуры, названия.
  Неисправленный текст предыдущего фрагмента автоматически не переносится.
- JSON переключён с `-oj` на `-ojf`, чтобы получить token scores.
- Низкие оценки декодера помечают фрагмент для проверки, текст не удаляется.
  Это не калиброванная вероятность правильности слова.
- Сохраняется перекрытие фрагментов по 2 секунды.
- Отбор перекрытия всё ещё по середине сегмента. Полноценного выравнивания слов/дедупликации швов пока нет.
- План границ сохраняется как checkpoint `asr-plan`, диагностика — `audio-quality`.
- Продолжение использует сохранённый план и атомарные checkpoints текста, без повторного добавления порций.
- В GUI при продолжении теперь меняются только память, потоки и GPU; модель и параметры распознавания сохраняются.
  Для применения другого ASR-профиля существующую запись нужно импортировать заново.

В SQLite добавлена совместимая миграция `segments.review TEXT DEFAULT ''`.
Пометки содержат причины: говорящий, граница, низкая уверенность Whisper.
Ручная правка снимает пометку и инвалидирует сводку, как и раньше.

### Два варианта сводки

`src/samarizator/summary.py`:

- Новый подробный map-промпт: существенные мысли, причины, условия, числа, решения, задачи,
  риски, вопросы и альтернативы; исключение приветствий и пустых повторов.
- Статусы пунктов: `proposed`, `agreed`, `cancelled`, `disputed`, `unspecified`.
- Сохраняются ссылки на ID исходных сегментов. Owner/due — только если явно указаны.
- Подробная сводка сохраняет содержательные пункты **всех map-блоков**, минуя сжатие reduce.
  Вводные тексты map-блоков также сохраняются. Возможны повторы между блоками.
- Финальный reduce делает краткую сводку до 9 пунктов. Промпт просит короткие тезисы;
  если пунктов больше 9, выдаётся ошибка с сохранением промежуточных map-блоков.
- Не реализовано отдельное глобальное согласование всех противоречий подробной сводки:
  там может быть раннее решение и его последующая отмена. Это история обсуждения.
- Результат имеет `brief`, `detailed`, `version=2`; старые `overview/items/topics/ledger/blocks`
  сохранены для совместимости. `summary_views()` умеет читать старые результаты.
- Cache digest учитывает промпт, SYSTEM, endpoint, модель и лимит ответа.
- Проверка evidence подтверждает существование сегментов, а не семантическую истинность вывода LLM.

### Интерфейс и Obsidian

`app.py`:

- Вкладки «Кратко · тезисы», «Подробная сводка», «Качество записи».
- Настройки «Качество и термины» с кнопкой профиля, VAD, путём модели, словарём и beam size.
- Причины проверки видны в таблице транскрипта.
- Обе сводки показывают таймкоды.

`knowledge.py`:

- Оба варианта сводки в одной заметке с ссылками на исходные сегменты.
- Темы для графа берутся из краткой и подробной сводок, чтобы не терять редкие темы.
- Статусы решений/задач отображаются текстом.
- Чекбоксы создаются только для согласованных действий краткой финальной сводки;
  исторические пункты подробной сводки не превращаются в активные задачи.
- Сохранена защита от перезаписи вручную изменённых экспортов.

### Контроль памяти

`process.py`: если RSS нельзя измерить или доступ запрещён, обработка прекращается;
нулевое показание больше не позволяет молча продолжать без контроля.
Остался watchdog на 90% суммарного RSS приложения и потомков. Это **не жёсткая квота ОС**.
Metal не полностью учитывается. Диаризация пока обрабатывает всю запись, с предварительной оценкой памяти.

## 4. Что проверено, и где остановились

**44 теста и Ruff прошли локально, на Ubuntu и macOS.** Проверяются в том числе:
паузы, диагностика, настройки, token scores, продолжение без дублей, сохранность подробных фактов,
статусы экспорта, GUI двух сводок, ограничения/отмена процессов и HTTP/API через MockTransport.
`bash -n start.sh` также прошёл.

Но **полный macOS CI пока красный**, готовым релизом ветку считать нельзя.

Промежуточный прогон `34446663351` / `ab7d576...` ещё выполнялся при последней проверке;
его статус нужно проверить заново. У ранних прогонов не было короткого тайм-аута.

В CI сейчас установка Whisper, загрузка моделей и smoke-тест разделены, на каждом macOS этапе
тайм-аут 5 минут. Smoke использует `say -v Samantha -r 100` и `scripts/smoke_audio.py`.
В нём принудительно memory=4, speakers=1, chunk=30, language=en; threads=8 берутся из профиля.
`SmokeStore.update()` выводит названия стадий без транскрипта.

**Не проверено:** качество реальных корпоративных ответов, рост точности на русских встречах,
работа full large-v3 на пользовательском M4 Pro, реальный пик памяти Metal, многочасовые встречи,
качество новой комбинации VAD/параметров на шуме и перебиваниях.
`docs/validation.md` описывает старую успешную версию `e3e497...`; это не подтверждение новой ветки.

## 5. Следующие шаги по приоритету

### P0. Довести эту ветку до подтверждённого рабочего состояния

1. Прочитать этот документ и diff относительно main. Сохранить все пользовательские изменения.
2. Проверить актуальные статусы трёх CI-прогонов выше; остановить устаревшие, если есть доступ.
3. Исправить тестовый аудиофайл: получить детерминированную длительность существенно больше 60 секунд,
   проверить её FFprobe **до** ASR, вывести план границ. Можно использовать закреплённый публичный
   речевой WAV и FFmpeg-конкатенацию вместо зависимости от системного TTS.
4. Разобраться с длительным Whisper. На одном коротком речевом WAV отдельно измерить время:
   исходный вариант, `-ojf`, VAD, 4/8 потоков, CPU/Metal при допустимом бюджете.
   Добавлять изменения по одному. Сохранить точную версию CLI, команду и лог для тестового аудио.
   Это план диагностики, не установленная причина. Не маскировать проблему простым снятием тайм-аута.
5. Сохранить диагностические логи тестового CLI как CI artifact при ошибке/тайм-ауте.
   Сейчас `run_command` пишет их в TemporaryDirectory; журнал процесса не попал в отчёт о тайм-ауте.
   Не включать автоматическую публикацию пользовательских транскриптов/ключей.
6. После исправления получить зелёные тесты и реальный macOS smoke на нескольких фрагментах:
   текст, говорящие, монотонные/разумные таймкоды, VAD, план, checkpoints, продолжение.
7. Обновить документацию с фактическими результатами, перенести ветку в main обычным PR/merge
   с проверкой актуального main, дать пользователю простые команды обновления.

### P1. Измеряемое улучшение ASR и проверка сомнительных мест

- Несколько примеров пользователя: чистая речь, шум, термины/числа, перебивания, русско-английская смесь.
- Сравнение текущей пользовательской модели и full large-v3; VAD on/off, память, скорость, WER/CER,
  отдельно ошибки в фамилиях, суммах, датах и отрицаниях. Не выбирать модель по размеру одному.
- Второй ASR-проход только для сомнительных интервалов, с контекстом по краям и ограниченным бюджетом.
- Хранить исходный и повторный варианты и причины проверки; не заменять факты молча.
- Прослушивание по таймкоду, фильтр «требует проверки», выравнивание слов на швах и защита от дублей.
- Шумоподавление/нормализацию вводить только после A/B на реальных примерах: они могут портить речь.
- При необходимости улучшить глобальное согласование решений подробной сводки, сохранив полный реестр фактов.

### P2. Live (пока не реализован)

- Штатный ScreenCaptureKit/разрешения macOS, раздельные микрофон и системный звук.
- Корпоративные ограничения не обходить; при запрете нужен согласованный путь с IT.
- Постоянно загруженный локальный Whisper вместо запуска CLI для каждого маленького окна.
- Ограниченный кольцевой буфер и очередь на диске, backpressure при отставании распознавания.
- Черновой и подтверждённый текст, обработка перекрытий, стабильные ID сегментов/говорящих.
- Инкрементальные краткая/подробная сводки корпоративной моделью без отправки всего текста каждый раз.
- Финальный качественный проход после остановки; восстановление после прерывания и контроль памяти.

## 6. Как продолжить работу

В новом checkout:

```bash
git clone --branch quality-m4-dual-summaries https://github.com/Igibaev/samarizator.git
cd samarizator
uv sync --frozen --python 3.12 --extra diarization --extra dev
uv run --frozen --extra diarization --extra dev ruff check src tests scripts
QT_QPA_PLATFORM=offscreen uv run --frozen --extra diarization --extra dev pytest -q
```

Для экспериментального запуска на Mac: `./start.sh --quality`.
Не рекомендовать как законченный релиз до P0. Для новых параметров ASR импортировать запись заново;
для новых форматов сводки достаточно снова нажать «Создать сводку» на существующем тексте.

Ключевые файлы: `config.py`, `audio_quality.py`, `media.py`, `worker.py`, `summary.py`,
`knowledge.py`, `app.py`, `store.py`, `process.py`, `setup_models.py`, `start.sh`,
`tests/test_quality.py`, `tests/test_media_gui.py`, `scripts/smoke_audio.py`, `.github/workflows/ci.yml`.
Пользовательское описание параметров — `docs/quality.md`.

Примечание для продолжения в прежнем агентском workspace:
локальный checkout `/workspace/scratch/d8dccd15d7a8/samarizator` оставался на старом main,
а изменения публиковались GitHub API через tree/commit/ref, поскольку git push не имел credentials.
Поэтому локальные staged/unstaged изменения могут уже соответствовать опубликованной ветке;
не считать их автоматически неопубликованной работой и не сбрасывать без сверки дерева.
Есть старый stash `WIP TLS fix before reviewing user updates`: он основан на более ранней версии,
перекрывает пользовательские правки truststore/API и не нужен для продолжения этой ветки.
Нельзя применять его вслепую. Свежий clone рабочей ветки — наиболее простой старт.
