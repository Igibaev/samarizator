# Зависимости и модели

## Рекомендация для M4 Pro / 48 ГБ

Для максимально качественной русской транскрибации начните с полной мультиязычной
`large-v3` и профиля качества:

```bash
git switch quality-m4-dual-summaries
git pull --ff-only
./start.sh --quality --large-v3
```

Команда скачивает веса с официального хранилища конвертированных моделей whisper.cpp,
выбирает их в настройках и ставит бюджет приложения 16 ГиБ. Загрузка нужна один раз;
модель хранится в:

```text
~/Library/Application Support/Samarizator/models/ggml-large-v3.bin
```

Далее запускайте `./start.sh`. Чтобы применить новую модель к уже добавленному аудио,
нажмите **«Распознать заново»**, а не «Распознать / продолжить». Параметры продолжения
фиксируются для записи, чтобы не смешивать результаты разных моделей.

## Какую Whisper выбрать

Все варианты в таблице мультиязычные. Размеры приведены по таблице whisper.cpp;
скорость и пик памяти зависят от версии whisper.cpp, длительности фрагмента и CPU/Metal.

| Модель | Размер весов | Когда выбирать |
|---|---:|---|
| Podlodka Turbo | ~1,6 ГиБ | Русская речь (по умолчанию): large-v3-turbo, дообученная на русских данных — пунктуация, шум, меньше галлюцинаций в тишине |
| `large-v3` | 2,9 ГиБ | Первая рекомендация для максимальной точности на M4 Pro / 48 ГБ |
| `large-v3-q5_0` | 1,1 ГиБ | Меньше места и памяти; квантование может немного изменить результат |
| `large-v3-turbo` | 1,5 ГиБ | Существенно быстрее; OpenAI описывает небольшое снижение точности относительно `large-v3` |
| `large-v3-turbo-q5_0` | 547 МиБ | Самый лёгкий из этих вариантов; больше компромиссов ради скорости и памяти |

**Podlodka Turbo** — [bond005/whisper-podlodka-turbo](https://huggingface.co/bond005/whisper-podlodka-turbo)
(Apache 2.0). Приложение берёт файл весов whisper.cpp из списка файлов репозитория
`smkrv/whisper-podlodka-turbo-coreml` (полная точность предпочтительнее квантованной), а если
там его нет — из `JoaoZaokk/whisper-podlodka-turbo-ggml`, конвертации той же модели.
CoreML-часть не нужна: whisper.cpp в приложении работает на Metal. Скачанный файл
проверяется по сигнатуре ggml и сохраняется как `ggml-podlodka-turbo.bin`.

Слово `turbo` означает ускоренную архитектуру, а `q5_0` — квантованные веса. Это не
строгая лестница качества для любой записи: правильнее прогнать один эталонный файл через
две модели и сравнить ошибки в именах, числах, терминах и пропуски целых фраз.

Полная `large-v3` устанавливается автоматической командой выше. Альтернативы можно
скачать вручную, например:

```bash
mkdir -p "$HOME/Library/Application Support/Samarizator/models"
curl -L --fail --retry 5 \
  -o "$HOME/Library/Application Support/Samarizator/models/ggml-large-v3-turbo.bin" \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo.bin
```

После загрузки откройте **Настройки → Распознавание речи · локально → Модель Whisper
(.bin) → Выбрать…**, укажите файл и сохраните настройки. Удалять прежнюю модель не нужно:
для отката просто выберите старый `.bin`. Для полной `large-v3` оставьте бюджет 16 ГиБ;
проверка приложения требует, чтобы оценка `размер модели × 2,5 + 600 МиБ` занимала не
более 80% выбранного бюджета.

Актуальный список, размеры и ссылки: [whisper.cpp — Models](https://github.com/ggml-org/whisper.cpp/blob/master/models/README.md).
Описание `large-v3` и `turbo`: [OpenAI Whisper](https://github.com/openai/whisper/blob/main/README.md).

## Локальная модель сводок

Сводки составляет локальная GGUF-модель через llama.cpp. Её скачивают один раз на первом
экране (или Настройки → Основное → Сводки → «Сменить…»). Окно выбора показывает для
каждой модели размер на диске, память при работе и вердикт для этого Mac: «подходит»,
«будет работать медленно» (меньше рекомендованной памяти) или «не поместится» — такую
модель выбрать нельзя. Загрузка продолжается с места обрыва.

Память при работе = веса + KV-кэш контекста + ~1,5 ГБ на сервер. Это та же оценка, по
которой задача сводки проверяет, хватит ли памяти, перед стартом (`local_llm.preset_ram_gb`,
`check_fits`: не больше 85% памяти Mac). Контекст зависит от размера блока, поэтому на Mac
с 8 ГБ первый запуск ставит блок 8000 символов — так Qwen3 4B помещается в память.

| Вариант | Модель (Q4_K_M) | Размер | Память при работе | Рекомендуется |
|---|---|---|---|---|
| Максимальное качество | Gemma 4 26B-A4B | 16,9 ГБ | ≈ 23 ГБ | от 32 ГБ; смесь экспертов, 3,8B активных параметров |
| Точная | Qwen3-30B-A3B-Instruct-2507 | 18,6 ГБ | ≈ 25 ГБ | от 32 ГБ; смесь экспертов, ~3B активных |
| Быстрая для русского | GigaChat 3.1 Lightning (10B-A1.8B) | ≈ 6,4 ГБ | ≈ 11 ГБ | 16–24 ГБ (по умолчанию); Сбер, обучена на русском, 1,8B активных |
| Сбалансированная | Gemma 4 12B | 7,1 ГБ | ≈ 12 ГБ | 16–24 ГБ; аккуратнее, медленнее GigaChat |
| Предыдущее поколение | Gemma 3 12B | 7,3 ГБ | ≈ 12 ГБ | оставлена для уже скачавших |
| Лёгкая | Qwen3-4B-Instruct-2507 | 2,5 ГБ | ≈ 6,5–7 ГБ | 8 ГБ; проще формулировки |

Gemma 4 и GigaChat скачиваются из репозиториев Hugging Face (`unsloth`, `ggml-org`, `ai-sage`,
`bartowski` — по очереди): приложение берёт из списка файлов вариант Q4_K_M (если его нет —
ближайший: Q4_K_XL, Q4_K_S, Q4_0, Q5_K_M…), без файлов `mmproj` (зрение) и разбитых на
части. Размер GigaChat указан приблизительно: точный виден при загрузке. Контекст GigaChat —
до 32k токенов, этого хватает конвейеру при настройках по умолчанию.

**Удаление моделей.** Настройки → Основное → «Скачанные модели» → «Управлять…»: список всех
скачанных моделей и недокачанных загрузок с размером и пометкой «Используется», у каждой —
«Удалить». Удалённая текущая модель перестаёт быть выбранной, приложение предложит скачать
её снова или выбрать другую; записи и сводки не затрагиваются.

Можно выбрать и любой другой файл `.gguf` (кнопка «Выбрать…»), например корпоративно
одобренную модель, скачанную вручную. Подойдёт instruction-модель с хорошим русским,
контекстом от 32k токенов и шаблоном чата в GGUF. Рассуждающие («thinking») модели
работают, но их рассуждения отключаются.

**Сколько это занимает.** Конвейер обходит всю расшифровку блоками (по умолчанию 12000
символов), каждый блок разбирается и затем проверяется по исходным репликам. Двухчасовая
встреча — это примерно 100–130 тыс. символов текста, 20–40 запросов к модели и, на Mac с
M-процессором, ориентировочно 15–60 минут в зависимости от модели и чипа. Скорость
определяется в основном генерацией ответа; GPU (Metal) включён по умолчанию.

**Память.** Перед запуском приложение оценивает: размер модели + KV-кэш контекста +
1,5 ГБ, и не запускает задачу, если это больше 85% памяти Mac. Бюджет защиты памяти для
задачи сводки поднимается автоматически под модель.

**Контекст: почему сводка не обрывается.** Окно контекста llama-server задаётся под
самый большой запрос конвейера. Перед каждым запросом приложение считает токены промпта
токенизатором самой модели (`/tokenize` llama-server; без него — заведомо завышенная
оценка 1,5 символа на токен) и отдаёт ответу ровно оставшееся место:

- запрос, которому не хватает места на ответ, не отправляется — блок расшифровки, группа
  объединения или согласования решений делится пополам (вместо урезанной сводки);
- итоговый текст берётся из самого подробного реестра, который помещается вместе с
  ответом не короче 2048 токенов, иначе — из более сжатого;
- если итоговый текст упёрся в лимит ответа, модель дописывает его с места обрыва (до 4
  продолжений, видя материал и конец уже написанного); предупреждение остаётся, только
  если текст обрывается и после этого.

**Нагрев и скорость.** Всё ниже ускоряет работу и снижает нагрев, не меняя содержания
сводки:

- Распознавание идёт на GPU (Metal) — в разы быстрее и холоднее, чем на ядрах процессора.
  Раньше GPU был выключен, потому что контроль памяти видел только RSS, а память Metal в
  него не входит. Теперь на macOS контроль читает физический объём памяти процесса
  (`phys_footprint`, как «Память» в Мониторе системы) — он включает память GPU. Старые
  настройки переводятся на GPU один раз; выключить можно в «Для опытных».
- llama-server: модель целиком на GPU, поэтому CPU только выбирает токены — 4 потока без
  активного ожидания (`--poll 0`; по умолчанию потоки крутятся в цикле и греют процессор).
- Спекулятивное декодирование `ngram-mod`: когда ответ повторяет уже бывший в контексте
  текст (цитаты из расшифровки, черновик при проверке, реестр в итоговом тексте), модель
  проверяет сразу пачку токенов вместо одного. Проверка сохраняет распределение модели,
  поэтому результат тот же, только быстрее. Если сервер не запустится с этим режимом, он
  перезапускается без него.
- JSON-ответы без отступов и переносов строк: меньше токенов на то же содержание.
- «Беречь Mac от перегрева» (включено): если macOS сообщает о сильном нагреве
  (`thermalState` serious/critical), между шагами делается пауза до 3 минут, пока Mac не
  остынет. На холодном Mac пауз нет.

**Алгоритм «конспект» (по умолчанию, `summary_notes.py`).** Генерация токена на Apple
Silicon требует прочитать из памяти активные веса модели (1–2 ГБ), поэтому писать модель
может в 10–20 раз медленнее, чем читать. Алгоритм устроен так, чтобы модель читала много,
а писала один раз:

- **Компактный вход.** Реплики — строки `[12] текст` (`[12?]` — сомнительная расшифровка)
  вместо JSON: служебная разметка занимала ~40% входа. В блок того же размера входит
  примерно в полтора раза больше речи, поэтому блоков меньше.
- **Короткий выход.** Пункт — одна строка `Вид [номера] текст | отв: … | срок: … |
  статус: …`; неизвестные поля не пишутся. Форму ответа держит грамматика GBNF (она же
  работает в MLX через llguidance), поэтому ответ всегда разбирается.
- **Проверка из кэша.** Расшифровка стоит в начале и запроса конспекта, и запроса проверки,
  задание — после неё. llama-server (и MLX) переиспользует уже прочитанное начало, так что
  проверка почти ничего не читает заново. Проверка пишет только правки: «Исправить N»,
  «Удалить N: причина», «Добавить» или «ВСЁ ВЕРНО»; неупомянутые пункты остаются как есть,
  удалить больше половины пунктов нельзя.
- **Сборка за один заход.** Конспект двухчасовой встречи (15–20 тыс. символов) читается
  целиком: краткая сводка (до 9 тезисов) и пересмотры решений приходят одним ответом.
  Пересмотр — строка «номера пунктов реестра → итоговый пункт», остальные решения и задачи
  программа переносит сама. Не поместилось или ответ не прошёл проверку — классическое
  многоуровневое объединение.
- **Замер.** В журнале: «Сводка готова за … (разбор …, сборка …, итоговый текст …)»; те же
  числа сохраняются в сводке (`timings`).

Классический алгоритм (JSON-реестры, полная проверка, объединение по уровням) остался:
«Для опытных» → «Алгоритм сводки» → «Классический».

**Ускорение сводки (без потери качества):**

- **Параллельные блоки.** llama-server запускается с несколькими слотами (до 4, по
  памяти Mac или вручную в «Для опытных»): блоки разбираются и проверяются одновременно.
  Генерация на Apple Silicon упирается в пропускную способность памяти, поэтому несколько
  запросов сразу почти не медленнее одного. KV-кэш хранится в 8 битах (q8_0) — вдвое
  меньше памяти на слот. Если сервер не стартует с ускорениями — обычный запуск.
- **Чистка входа.** Модель читает расшифровку без «эээ», повторов-заиканий и устойчивых
  слов-паразитов; сама расшифровка не меняется (`speech.py`).
- **Проверка присылает только правки** (keep / edit / add / removed): верные пункты не
  переписываются, а копируются из черновика; учёт каждого пункта и источников проверяется
  как раньше.
- **Модель отбора** (в духе Jev, но локально): Qwen3 0.6B (GGUF, ~0,6 ГБ) на встроенном
  llama-server отвечает yes/no «есть ли во фрагменте что-то по делу»; читается только
  вероятность ответа. Спрашиваются короткие фрагменты (до 300 символов), отсеиваются при
  уверенности от 90%. Сводка показывает, сколько реплик не вошло (`decide.py`).
- **Движок MLX (экспериментально).** «Для опытных» → «Движок сводок» → MLX. Отдельная копия
  модели в формате MLX (4 бит, mlx-community); процесс `samarizator.mlx_server` из той же
  сборки отвечает тем же API, что llama-server, JSON-ответы ограничены той же грамматикой
  (llguidance), общее начало промптов кэшируется. Работает один запрос за раз, поэтому
  сравните с llama.cpp на своих записях: несколько слотов llama.cpp могут оказаться не
  медленнее. При любом сбое MLX сводка продолжается на llama.cpp; вопросы по сводке всегда
  на llama.cpp, поэтому основная модель GGUF нужна в любом случае.

**Сделать заново.** «⋯» → «Сделать сводку заново…» (и кнопка под предупреждением в
итоговом тексте) отбрасывает все сохранённые промежуточные шаги и строит сводку с нуля;
прежняя сводка остаётся, пока новая не готова. Прерванную сводку можно продолжить с места
остановки или начать заново.

Из исходников модель скачивается так: `./start.sh --llm auto` (или `--llm qwen3-30b-a3b`).

## Зависимости и происхождение весов

Python-пакеты зафиксированы с хешами в `uv.lock`; `start.sh` использует `uv sync --frozen`. В готовом приложении FFmpeg, Whisper.cpp и llama.cpp собраны из исходников закреплённых версий (`packaging/macos/build.sh`); при запуске из исходников они ставятся Homebrew. Веса загружаются отдельно, не включаются в Git. `download-manifest.json` фиксирует SHA-256 полученных файлов для локального учёта; это не независимая криптографическая проверка опубликованного эталона. Корпоративный проверенный файл можно разместить вручную и выбрать в настройках.

| Компонент | Назначение | Первичный источник |
|---|---|---|
| Whisper.cpp, модель small-q5_1 | Локальное распознавание речи, CPU | https://github.com/ggml-org/whisper.cpp |
| GGML Whisper models | Мультиязычные веса | https://huggingface.co/ggerganov/whisper.cpp |
| PySide6 | Десктопный интерфейс Qt | https://doc.qt.io/qtforpython-6/ |
| FFmpeg | Извлечение первой аудиодорожки | https://ffmpeg.org/ |
| llama.cpp (llama-server) | Локальная модель сводок, Metal | https://github.com/ggml-org/llama.cpp |
| Qwen3 / Gemma 3 GGUF | Веса моделей сводок | https://huggingface.co/unsloth |
| PyInstaller | Сборка .app | https://pyinstaller.org/ |

Каждый сторонний компонент и набор весов имеет собственные условия лицензирования. Установка зависимостей не перелицензирует их. Для корпоративного распространения проверьте условия конкретных используемых версий, моделей, Qt/PySide6 и сборки FFmpeg. Этот репозиторий не включает веса моделей. Собранный .dmg включает Silero VAD (и другие модели, если они встроены при сборке через `models/bundle.json`) — учитывайте их лицензии при распространении.
