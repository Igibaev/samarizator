# Качество транскрибации и два вида сводки

## Обновление на Mac M4 Pro / 48 ГБ

Закройте приложение, затем в папке репозитория:

```bash
git fetch origin
git switch quality-m4-dual-summaries
git pull --ff-only
./start.sh --quality
```

Команда скачивает небольшой локальный Silero VAD v6.2.0 и включает профиль: бюджет 16 ГиБ,
8 потоков CPU, фрагменты около 90 секунд, поиск ближайшей паузы и beam size 5.
**Ваша выбранная модель Whisper, язык, корпоративный API и ключ сохраняются.**
Дальнейшие запуски: `./start.sh`. Те же параметры доступны в настройках на вкладке
«Качество и термины». Не запускайте установщик одновременно с приложением.

Для отдельного сравнения можно скачать и выбрать полную multilingual large-v3 (~3.1 GB):

```bash
./start.sh --quality --large-v3
```

Это явно меняет выбранную ASR-модель. Полная large-v3 — кандидат для сравнения,
а не обещание, что она лучше вашей текущей модели на любой записи.
Старые веса сохраняются; вернуться к ним можно в настройках.
При корпоративном TLS uv и Python используют системное хранилище доверия.
Корневой сертификат компании должен быть установлен доверенным способом; проверка TLS не отключается.

## Если текст остался прежним или сводка завершилась ошибкой

В заголовке обновлённого приложения указано «Сводки 2.5» и короткий Git-коммит.
Если видны только вкладки «Расшифровка» и «Сводка», проверьте ветку
и папку запуска: обычный `git pull` в `main` не устанавливает эти доработки.

Определение собеседников удалено: интерфейс показывает единую расшифровку по времени,
а в запрос сводки передаются текст, таймкод и признак необходимости проверки. Голосовые
ONNX-модели и `sherpa-onnx` больше не устанавливаются и не расходуют память. Уже скачанные
файлы `.onnx` могут остаться в локальной папке моделей, но приложение их не читает;
автоматически они не удаляются, чтобы обновление не стирало пользовательские файлы.

«Распознать / продолжить» использует сохранённые фрагменты и настройки записи.
Для полного прохода с текущей моделью, словарём и параметрами нажмите
**«Распознать заново»**. Создаётся новая запись; прежний текст и ручные правки сохраняются.
При одинаковых настройках Whisper может снова выдать тот же текст — это само по себе не ошибка.

После завершённого распознавания нажмите **«Создать сводку»**: результат откроется
на вкладке кратких тезисов; подробный вариант доступен отдельно. Расшифровка остаётся
близкой к исходной речи, а содержательное обобщение выполняет корпоративная модель.

Сохранённая причина сбоя теперь видна под названием записи и доступна через
**«Скопировать ошибку»**, в том числе после перезапуска. Некорректный JSON модели
повторяется до трёх попыток. Распространённые безопасные вариации JSON корпоративных
моделей (например, `key_points`, `type`, `segment_ids`) приводятся к внутренней схеме,
но отсутствующие ссылки на исходные реплики никогда не придумываются. Если API сообщает
об обрезанном или устойчиво некорректном ответе при подготовке подробного блока, вход
делится пополам (до трёх уровней); успешные части сохраняются. Если ошибается только
финальное сжатие, подробная сводка не теряется: краткий вариант собирается из уже
проверенных пунктов и помечается предупреждением.
Ошибка авторизации, сети или корпоративного сертификата требует исправления
соответствующей настройки. Реальные ответы корпоративного API разработчику недоступны;
автоматическое восстановление не гарантирует успех при любой ошибке провайдера.

## Метки источников в сводках

В краткой, подробной сводке и итогах по решениям у каждого тезиса показан ровно один
компактный значок **▶** — без списка мелких таймкодов. Наведите курсор: появятся интервалы
и актуальный текст всех исходных реплик тезиса. Это сохранённая расшифровка, а не новая
генерация модели; ручные исправления учитываются. Реплики загружаются из SQLite только
при наведении, поэтому полный текст встречи не копируется в каждую вкладку.

Нажатие на **▶** проигрывает все источники тезиса. Реплики сортируются по времени;
пересекающиеся интервалы и промежутки до 5 секунд объединяются в один отрывок.
По краям добавляется секунда контекста, поэтому могут прозвучать и соседние реплики.
Удалённые друг от друга отрывки проигрываются автоматически по очереди, без длинных
промежутков между ними; переход между отрывками может сопровождаться короткой паузой запуска
плеера. Индикатор под вкладками показывает текущий отрывок и общее число отрывков.
«Стоп», выбор другой записи или нажатие другого значка отменяют прежнюю очередь.
Звук читается из исходного файла; копии отрывков и большой склеенный файл не создаются.

Следующий клик останавливает предыдущую очередь. Общая кнопка **«■ Стоп»** под вкладками
доступна и при чтении сводки. Для звука нужен `ffplay` из установленного FFmpeg; исходный
файл должен оставаться доступным. Видеоокно при этом не открывается.

Значки появляются и у ранее сохранённых сводок — повторный запрос к корпоративной модели
не требуется. Все реплики одного тезиса объединены под одним значком.
В Obsidian остаются обычные ссылки на блоки расшифровки; интерактивное прослушивание
реализовано в desktop-приложении.

## Что изменилось

- Границы сдвигаются к паузам в пределах ±6 секунд от целевого времени. Поиск уровня
  сигнала ничего не удаляет из аудио. Фрагменты сохраняют перекрытие по 2 секунды.
  При отсутствии паузы остаётся временная граница с пометкой для проверки.
- Из-за перекрытия соседние фрагменты иногда распознают одни и те же слова на стыке дважды.
  Перед сохранением нового фрагмента его начало сравнивается с концом уже сохранённого текста
  (до 12 слов, без учёта регистра и пунктуации). Текст не удаляется автоматически:
  при пересечении времени около границы появляется пометка
  «возможный повтор на стыке — сверить по аудио». Реальные повторные ответы сохраняются.

- Whisper.cpp использует локальный Silero VAD: порог 0.4, минимальная речь 150 мс,
  пауза 500 мс, запас по краям 250 мс. Параметры выбраны как начальный вариант,
  а не измеренный оптимум для ваших записей. Очень тихую речь VAD может пропустить;
  для сравнения отключите его и импортируйте ту же запись заново.
- Словарь до 800 символов передаётся Whisper как подсказка: фамилии, названия проектов,
  аббревиатуры. Лучше короткий список релевантных слов; подсказка может смещать результат.
  Неисправленный текст предыдущего фрагмента не переносится автоматически.
- Полный JSON Whisper используется для пометок низкой уверенности декодера.
  Это **не процент точности**. Текст сохраняется, сомнительные места предлагаются к проверке.
- Вкладка «Качество записи» показывает уровень RMS и возможное отсечение пиков
  после приведения дорожки к mono PCM16. Это не измерение отношения сигнал/шум
  и не полная диагностика исходных каналов. Шумоподавление автоматически не применяется.
- План границ сохраняется в SQLite и переиспользуется при продолжении. Каждая порция
  текста фиксируется вместе с контрольной точкой; продолжение не дублирует порции.

## Память и скорость

По умолчанию профиль использует CPU: ограничитель останавливает процессы при 90% бюджета RSS.
Это контролируемая остановка с продолжением, **не жёсткая квота macOS**; краткий всплеск возможен.
Полная large-v3 на CPU может работать заметно дольше длительности записи.
Metal можно включить отдельно в настройках для сравнения скорости. Память Metal не полностью
учитывается RSS, поэтому при нём нельзя обещать соблюдение выбранного общего бюджета.
Запись не загружается целиком для ASR: FFmpeg и Whisper обрабатывают её фрагментами.

## Как получить новый результат

Для новых параметров ASR **импортируйте исходный файл как новую запись**. Старую можно сохранить
для сравнения. Продолжение существующей записи сохраняет модель, словарь, язык, VAD и план разбиения;
менять при продолжении можно бюджет, число потоков и ускорение.

Для двух сводок уже распознанной записи достаточно снова нажать «Создать сводку».
Только текст отправляется на настроенный API; адрес и модель не меняются профилем.

- **Кратко · тезисы:** короткий вводный абзац и не более 9 ключевых пунктов; без ограничения в 300 символов на тезис.
- **Подробная сводка:** содержательные итоги исходных блоков и полный набор извлечённых
  существенных пунктов, сгруппированных в темы, решения, задачи, риски и открытые вопросы.
  Здесь сохраняются аргументы, условия, числа и альтернативы, если они есть в записи.
  Возможны повторы между блоками. Это сводка обсуждения, не последовательная копия реплик.
  Если в записи решение сначала приняли, а потом отменили или пересмотрели — здесь останутся
  **обе** записи, в хронологическом порядке: это полная история, ничего не удаляется.
- **Итог по решениям:** отдельная вкладка. Модель отдельным проходом смотрит на все решения
  и задачи из «Подробной сводки» и возвращает по одной итоговой записи на каждое — с последним
  известным статусом, если было более позднее изменение или отмена. Полная история при этом
  никуда не девается — «Итог» это дополнительный взгляд, а не замена «Подробной сводки».
  Если модель не может понять итоговый статус из записи — она обязана пометить его как
  «не установлено», а не гадать. Насколько хорошо это работает на реальных решениях —
  не проверено, нужны реальные записи.

## Повторный проход по сомнительным репликам

Кнопка «Повторить сомнительные реплики» запускает второй проход Whisper только по репликам,
уже помеченным для проверки (граница фрагмента, низкая уверенность декодера) —
не больше 20 за один запуск. Каждая реплика вырезается с запасом ±2 секунды по краям для
контекста и распознаётся заново теми же моделью/VAD/beam size, что и основной проход
(их нельзя поменять без повторного импорта — как и при продолжении распознавания).

Результат **не заменяет текст автоматически**. Он сохраняется рядом как повторный вариант;
в таблице такая реплика помечена «есть повторный вариант», а при её выборе внизу появляется
сам текст-кандидат и кнопка «Принять повторный вариант». Ручная правка реплики отменяет
непринятый повторный вариант. Насколько такой проход в среднем лучше исходного — не измерено,
нужна проверка на реальных записях.

Над таблицей расшифровки — чекбокс «Только требующие проверки»: показывает только реплики,
отмеченные хотя бы одной причиной (граница фрагмента, низкая уверенность Whisper,
возможный повтор на стыке), вместо того чтобы листать всю запись целиком в поисках спорных
мест. Принятие нового текста не подтверждает автоматически границы;
их пометки сохраняются до ручной проверки.

Кнопка «▶ Прослушать реплику» открывает исходную запись через `ffplay` (ставится вместе
с ffmpeg) сразу на времени выбранной реплики, с запасом 2 с по краям, вместо того чтобы
искать нужный момент вручную в отдельном проигрывателе. «■ Стоп» останавливает воспроизведение.
Если `ffplay` не установлен, кнопка сообщит об этом — запись всё равно можно открыть целиком
кнопкой «Открыть исходную запись».

Обе вкладки дают доступ к источникам через значок ▶, экспорт в Obsidian содержит оба раздела
и обычные ссылки на сегменты с таймкодами.
Предложения, согласованные, отменённые и спорные решения различаются. В подробном разделе
могут соседствовать раннее решение и его позднейшая отмена: это история обсуждения.
Чекбоксы задач создаются только для явно согласованных действий краткого финального итога.
Тема, отсутствующая в краткой сводке, всё равно попадает в граф Obsidian из подробной.
Проверка ссылок гарантирует существование сегмента, но не доказывает истинность интерпретации модели.

## Проверка и следующие приоритеты

Автоматические проверки покрывают паузы, диагностику, низкие оценки декодера,
продолжение без дублей, сохранность подробных фактов и экспорт статусов.
GitHub Actions в проекте не используется; `scripts/smoke_audio.py` запускается вручную на Mac
с реальными FFmpeg, Whisper.cpp и VAD перед выпуском изменений.
`scripts/make_smoke_fixture.sh [output.wav] [min_seconds]` строит для него через `say`
речевую фикстуру заданной длины, проверяя фактическую длительность через ffprobe (а не
полагаясь на один текст, который раньше давал слишком короткую запись и один фрагмент вместо
нескольких). `smoke_audio.py` сам проверяет ffprobe и печатает план границ фрагментов до
запуска Whisper и падает сразу, если фикстура слишком короткая для второго фрагмента.
Синтетическая английская речь проверяет работоспособность конвейера, а не качество русских встреч.
Без размеченной записи пользователя прирост точности не измерен.

Следующий этап: проверить реальный запуск и скорость Whisper на Mac по сохранённым журналам,
остановку/продолжение, память и корпоративные сводки. Сравнение моделей и WER/CER сняты пользователем с плана.
После этого — live: отдельные разрешённые дорожки микрофона и системного звука,
постоянно загруженный Whisper, ограниченная очередь на диске, черновой/подтверждённый текст,
обновляемая сводка и финальная обработка после остановки. Live в этой версии ещё нет.
Захват системного звука будет использовать штатные разрешения macOS/ScreenCaptureKit;
корпоративный запрет не обходится.

Основания для интеграции: [CLI Whisper.cpp v1.9.2](https://github.com/ggml-org/whisper.cpp/blob/v1.9.2/examples/cli/cli.cpp),
[модели VAD](https://github.com/ggml-org/whisper.cpp/blob/v1.9.2/models/download-vad-model.sh).

## Безопасность повторного прохода и согласования

При смене страницы или записи повторный вариант нужно выбрать заново: кнопка принятия
не использует скрытый вариант из прежнего выбора. Предыдущий текст после принятия хранится
в базе; «Отменить принятие» возвращает его. Последующая ручная правка защищена от такого отката.
Пометка о границе не снимается принятием одних только слов.

Повторный проход проверяет хеш исходного файла и не смешивает разные версии записи.

Для длинной встречи согласование может остаться частичным: тогда это явно написано в разделе
«Итог по решениям». Если дополнительный запрос не удался, обе основные сводки всё равно
создаются. Полный реестр сохраняется; статус спорных решений нужно проверить по записи.

## Промпты 2.4 (история) и следующий этап

Сводка теперь ориентирована на читателя, который не слышал разговор: предмет, проблема,
обсуждённые варианты и результат. Подробные пункты сохраняют причины и условия; краткие
не должны терять центральную мысль ради списка задач. Дополнительных API-проходов не добавлено.
Первое пересоздание после обновления заново обработает блоки из-за нового промпта.
[Пример проверки качества](summary-prompt-check.md) · [План live по горячей клавише](live-plan.md).

## Сводки 2.5: полнота важнее скорости

По результатам пользовательской проверки версия 2.4 давала худшие сводки. Она заменена
новыми инструкциями с приоритетом точности и полноты; сняты требования одного вводного
предложения и 300 символов на короткий тезис. Сводка не обязана искусственно укладывать
каждую тему в цепочку «проблема → причина → результат».

Теперь блок получает соседние исходные реплики, затем его черновик проходит дополнительную
сверку с транскриптом. Проверяются пропуски, искажения, условия и статусы. Каждый пункт
черновика должен быть учтён; удаление требует объяснения и источников. Незавершённая проверка
показывается предупреждением, первоначальный вариант сохраняется и повторно используется
при следующей попытке. Полная схема и ограничения — [Проверка по источнику](summary-source-review.md).

Для применения обновления достаточно снова нажать «Создать сводку», распознавать аудио
заново не требуется. Новый промпт и вход инвалидируют старые checkpoints суммаризации.
Запросов стало больше; скорость и стоимость API уступают приоритет полноте результата.
