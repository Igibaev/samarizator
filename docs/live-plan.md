# Live: план разработки для Mac M4 Pro / 48 ГБ

Статус: живая часть плана закрыта и проверена на целевом Mac (macOS 15.6.1, M4 Pro). Кнопка
пишет выбранные источники потоком, системный звук идёт через штатный ScreenCaptureKit, уровни
по дорожкам измеряются, готовые фрагменты распознаются по ходу записи, закрывающий проход
доделывает хвост. Упаковка отложена: на время MVP запуск остаётся через `./start.sh`.

**Решение пользователя (13 сентября 2026):** сводка нужна после встречи, а не во время неё,
поэтому этапы 2 и 3 в исходном виде отменены. Потоковый Whisper с черновым хвостом ухудшил бы
качество (окна по 15–30 секунд вместо полного контекста) ради текста, который читают уже после
разговора. Вместо него сделано догоняющее распознавание: та же геометрия фрагментов и то же
качество, но ожидание после встречи сводится к хвосту. Глобальная горячая клавиша также
отменена по просьбе пользователя. Приоритет — качество итоговой сводки.
Цель: кнопка запускает запись выбранных источников, локальный Whisper распознаёт готовые
фрагменты по ходу встречи, а после остановки быстро получаются краткая и подробная сводки.

## Пользовательский сценарий

1. В настройках выбрать источник записи, модель Whisper, бюджет памяти и корпоративный API.
   Аудио остаётся локальным; в облачную модель уходит только текст и только по кнопке.
2. Кнопка в окне запускает и останавливает запись. Глобальная комбинация отменена.
3. Индикатор записи и таймер видны постоянно, рядом — какой фрагмент сейчас распознаётся.
4. Повторное нажатие прекращает захват сразу. Закрывающий проход доделывает хвост, дальше
   обычная проверка расшифровки, краткая и подробная сводки и экспорт в Obsidian.
5. Уровни по дорожкам измеряются после остановки: пустая дорожка видна сразу, а не на слух.

## Порядок реализации и критерии готовности

| Этап | Работа | Как принимаем |
|---|---|---|
| 1. Запись | **Сделано:** кнопка Qt запускает FFmpeg/AVFoundation, пишет WAV на диск, устройство выбирается в настройках по имени. Глобальная клавиша отменена пользователем | Автотесты на жизненный цикл, финализацию WAV и отказ разрешения; запись проверена на целевом Mac. Не проверены: сон, смена устройства на ходу, длинная запись |
| 2. Догоняющее распознавание | **Сделано** вместо потокового Whisper: готовые фрагменты уходят в обычный конвейер прямо во время записи, закрывающий проход доделывает хвост | Тест сравнивает план, собранный по ходу записи, с планом целой записи на реальном аудио с поиском пауз — совпадают. Не проверено на целевом Mac: часовая встреча, конкуренция за CPU с захватом |
| 3. Live-сводка | **Отменена:** сводка нужна после встречи | — |
| 4. Системный звук | **Сделано для записи:** helper ScreenCaptureKit отдаёт системный звук потоком, устройство петли — запасной путь; при «оба» дорожки пишутся раздельными каналами одного WAV на общей шкале времени, уровни по каналам измеряются после остановки | Автотесты на разводку пайпа, отказ разрешения и ошибку helper'а; на macOS 15.6.1 проверены обе дорожки и распознавание. Не проверены: наушники против динамиков, смена устройств на ходу, дрейф на длинной записи, поведение при запрете политикой |
| 5. Упаковка | **Отложена на время MVP** (решение пользователя 13 сентября 2026): пользователь один, запуск через `./start.sh` работает, разрешения выданы Terminal. Нужна, когда приложением начнёт пользоваться кто-то ещё | Когда возьмёмся: bundle с иконкой и Info.plist поверх текущего checkout, свой сертификат для стабильной подписи, оба helper'а внутри бандла и подписаны той же идентичностью, разрешение выдаётся «Samarizator» и переживает пересборку |

Как устроено догоняющее распознавание: FFmpeg пишет WAV с `-flush_packets 1`, поэтому файл
читается по ходу записи. Встреча заводится в базе с первой секунды и указывает на растущий
файл. Фаза `catchup` в worker'е опрашивает доступную длительность и планирует разрез у очередной
цели, как только записано `target + 11` секунд: ровно столько нужно поиску паузы (окно ±6 с) и
проверке «не ближе 5 секунд к концу». После этого разрез окончателен, поэтому план по ходу
записи — строгий префикс плана целой записи. Хвост намеренно не берётся: его геометрия
определяется только в конце. При остановке источник переключается на готовый файл, и обычный
проход продолжает сохранённый план.

## Архитектура

- `native/macos-capture/`: helper захвата, горячей клавиши и системных разрешений.
  Выбор API глобальной клавиши окончательно закрепить после прототипа на целевой macOS;
  Qt shortcut только внутри окна не удовлетворяет требованию.
- `src/samarizator/live/session.py`: состояния idle → recording → finalizing → done;
  interrupted/error восстанавливаются явно. Один координатор владеет сессией.
- `live/audio.py`: ограниченная очередь, конвертация PCM, временная шкала и файлы порций.
- `live/asr.py`: адаптер постоянного процесса Whisper, смена чернового хвоста и фиксация текста.
- `live/summary.py`: планировщик изменений, версии сводки и курсор последнего обработанного ID.
- Существующие `summary.py`, `SummaryBrowser`, экспорт и проверки evidence переиспользуются.
  Файловый worker сейчас запускает Whisper по фрагментам; для live нужна отдельная постоянная
  сессия модели, иначе повторная загрузка весов будет увеличивать задержку.
- IPC helper ↔ Qt через pipes с ограничением размера сообщений. API-ключ helper не получает.
  События: started, audio_chunk, device_changed, stopped, error; каждая порция имеет session_id,
  source, seq и временные границы. Аудио закрывается атомарно; SQLite отмечает готовые порции.
- Новые таблицы/поля сессии, порций, ревизий текста и версии сводки — совместимой миграцией.
  Стабильный segment ID сохраняется при правке; ревизия меняется и инвалидирует зависимые пункты.

## Скорость, память и качество

- Начальная настройка для измерений: окно 15–30 секунд, обновление черновика раз в 3–5 секунд,
  перекрытие 1–2 секунды. Слишком частые полные декодирования окна повышают нагрузку:
  после замера подобрать шаг, VAD и модель. Тишина не должна порождать текст.
- Не фиксировать нестабильный хвост; совпадения на перекрытии выравнивать по времени и словам.
  Реальные повторения речи сохранять. В корпоративный API идёт только подтверждённый текст.
- Одна выбранная модель Whisper в памяти; размер и ускорение не меняются автоматически.
  После остановки по желанию более точный файловый проход с заменой ссылок на ревизии,
  но не в первом live MVP. Полный повторный ASR не запускать скрыто.
- Стартовый бюджет 16 ГиБ, настраивается. RAM содержит ограниченные очереди, запись пишется
  порциями на диск; manifest позволяет собрать полную запись и воспроизвести старые источники.
  При отставании ASR очередь остаётся на диске; UI показывает задержку. При недостатке места
  захват останавливается явно, вместо молчаливой потери звука.
- ASR и файловое распознавание не должны одновременно загружать тяжёлые модели.
  RSS watchdog защищает CPU-режим, но не является жёсткой квотой. Ускорение Metal оценивать
  отдельно по общей памяти macOS, RSS не отражает весь расход GPU.
- До обещаний скорости замерить прогрев, p50/p95 задержки, пиковую память и RTF на выбранных
  пользователем весах. Для стабильного live средняя обработка должна успевать за поступлением
  аудио (RTF < 1); M4 Pro / 48 ГБ само по себе этого не гарантирует для любой модели.

## Обновление сводки без полного пересказа встречи каждый раз

- Стартовая частота — не чаще раза в 45–60 секунд, только при появлении нового текста;
  по кнопке можно запросить обновление. Одновременно выполняется один запрос модели.
- Отправлять новые сегменты плюс ограниченный контекст активных тем с реальными source ID.
  Строить новый подробный блок и изменения текущих итогов одним структурированным ответом.
  Полная история блоков хранится локально; live-контекст не растёт со всей записью.
- У тем и задач стабильные ID; ответ добавляет/уточняет/отменяет пункты, а не стирает
  прежние данные. Применение патча и фиксация курсора атомарны; устаревший ответ отвергается.
- Для возврата к ранней теме подбирать ограниченный набор прежних пунктов из SQLite
  по словам/названиям и ID. Не считать краткую предыдущую сводку единственным источником истины.
- После ручной правки подтверждённой реплики пересчитать зависимые блоки, затем итог;
  не оставлять сводку привязанной к устаревшей версии текста.
- При недоступности API запись и ASR продолжаются. Повторы с задержкой ограничены,
  накопленный текст догоняется блоками; публичного запасного API нет.
- После остановки итог собирать из полного подробного реестра, проверять поздние отмены
  и связи источников. Черновые live-сводки не использовать вместо полного реестра.

## Системный звук и macOS

Основной путь — штатный ScreenCaptureKit. `native/macos-capture/main.swift` — helper на ~200
строк: поднимает `SCStream` с `capturesAudio`, сводит каналы в моно и пишет сырой PCM
(float32, 48 кГц, моно) в stdout; события идут построчным JSON в stderr.
`excludesCurrentProcessAudio` исключает звук самого helper'а.

**Измерено на macOS 15.6.1 (M4 Pro, 5-секундные прогоны `scripts/diagnose_system_audio.sh`):**
регистрация выхода `.screen` полностью глушит аудио — 0 буферов против 262 без неё. Поэтому
видеовыход не регистрируется вообще: у ScreenCaptureKit нет потока только со звуком, но
размера кадра в конфигурации достаточно, читать кадры не требуется. Флаг `--with-video`
оставлен как проба на регрессию. Кадр 2×2 при этом тоже не даёт звука, поэтому размер
оставлен 128×72; какой из двух факторов ломал захват в первой версии — не разделяли, рабочая
комбинация проверена целиком.

Python-сторона (`screencapture.py`) собирает helper через swiftc с зафиксированным deployment
target macOS 13 и проверяет режимом `probe` разрешение и наличие дисплея. `live.py` создаёт
`os.pipe()`, отдаёт FFmpeg читающий конец как `pipe:<fd>` через `pass_fds` и запускает helper
с пишущим концом на stdout. Так stdin FFmpeg остаётся свободным для `q`, а смерть helper'а
закрывает пайп и корректно завершает вход FFmpeg. Обратное давление намеренное: если FFmpeg
не успевает, helper блокируется на записи, а не теряет звук молча.

Разрешение TCC («Запись экрана и системного звука») выдаётся приложению-хозяину: при запуске
из Terminal его и нужно включить, причём действует оно со следующего запуска. Отдельный bundle
с собственным разрешением — вопрос этапа 5 (подпись и нотаризация).

Запасной путь — устройство петли (BlackHole, Loopback, интерфейс с аппаратным loopback),
которое AVFoundation показывает обычным входом и гейтится микрофонным разрешением. Устройства
опознаются и сохраняются по имени, а не по индексу: AVFoundation перенумеровывает входы при
подключении устройств. Путь нужен там, где ScreenCaptureKit запрещён политикой.

Незакрытое: собственный проигрыватель приложения — отдельный процесс ffplay, поэтому
`excludesCurrentProcessAudio` его не исключает; сейчас это безопасно только потому, что UI
останавливает воспроизведение на время записи. Точечное исключение приложений даст
`SCContentFilter(display:excludingApplications:exceptingWindows:)` либо process taps
(`AudioHardwareCreateProcessTap`, macOS 14.4+), если понадобится брать звук только одного
приложения.

Замер на FFmpeg 6.1: `amerge` двух моно-входов даёт канал 0 — микрофон, канал 1 — системный
звук, файловый конвейер сводит их в моно с усреднением, то есть −6 дБ на каждый источник
относительно одиночной записи. Компенсацию усилением при захвате намеренно не вводим: это
изменило бы исходную запись. Если на реальных встречах это ухудшит ASR, вариант — суммировать
каналы (`pan=mono|c0=c0+c1`) для live-файлов с контролем клиппинга, после A/B на примерах.

Микрофон остался на AVFoundation через FFmpeg: он уже работал, и перенос его в helper ничего
не добавляет к записи на диск. С macOS 15 ScreenCaptureKit отдаёт микрофон отдельным потоком
того же `SCStream` — это стоит рассмотреть на этапе потокового Whisper, когда обе дорожки
понадобятся синхронными в памяти, а не только в общем файле.

При запрете корпоративной политикой показывать недоступность системного источника и доступные
разрешённые варианты: микрофон или импорт записи встречи. Не обещать, что выдача обычного
разрешения пользователем отменит MDM-запрет. Обход ограничений в план не входит.
При воспроизведении через динамики микрофон может повторно захватить удалённую речь;
раздельные дорожки сами по себе не решают эхо. До обработки эха рекомендовать наушники.

Упаковка helper: стабильный bundle ID и описание использования микрофона, проверка подписи
и поведения TCC после обновления. Прототип может собираться локально с Xcode Command Line
Tools; для готового распространения потребуется отдельное решение по подписи/notarization.
