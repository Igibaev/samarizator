# ИИ-компаньон для macOS — design.md

Версия: 1.2  
Дата: 16 сентября 2026  
Статус: спецификация дизайна и поведения; приложение в рамках этой задачи не реализуется.  
Связанный файл: `image-prompt.md`.

## 1. Решение и порядок приоритетов

Компаньон состоит из двух связанных поверхностей: программного правого крыла, которое визуально бесшовно продолжает аппаратный notch, и полки задач ПО ЦЕНТРУ ПОД notch. Глаза и обе кнопки находятся в правом крыле, на одной высоте с вырезом. Между notch и крылом нет зазора, шва или отдельного левого скругления: они читаются как единый чёрный силуэт. Слева направо внутри крыла: два белых глаза, запись с транскрибацией, саммаризация. Под самим notch висят до трёх задач текущего фокуса. Наведение на глаза раскрывает подробности задач внизу. Горизонтальные жесты ведут к буферу обмена и записям в правой панели поверх окон.

Изменение версии 1.2 по просьбе пользователя: ВСЯ группа «глаза + запись + саммари» образует бесшовное правое продолжение notch. Старую шапку с глазами под notch удалить. Отдельную плавающую капсулу с зазором справа не создавать. Не дублировать глаза в раскрытой панели; задачи не переносить вправо вслед за кнопками. Это уточнение заменяет старое расположение в предыдущих изображениях и промтах для Claude Code.

Не превращать продукт в чат, бесконечный список задач, канбан или дашборд. Главный объект — глаза и три обещания себе. Буфер и записи — дополнительные рабочие поверхности.

При расхождении источников использовать приоритет:

1. Прямые последующие указания пользователя.
2. Правила и числа этого документа.
3. Промт генерации.
4. Сгенерированная картинка как ориентир композиции и материалов.

Все размеры, интервалы, цвета и сроки ниже — предложенные проектные решения, а не требования Apple. Отдельно подтверждённые пользователем требования перечислены в следующем разделе. Возможности интеграций описаны как условия будущей реализации, а не как уже работающие функции.

## 2. Что должно быть сохранено

| Требование пользователя | Зафиксированное решение |
| --- | --- |
| Глаза и обе кнопки в продолжении notch | Бесшовное правое крыло; глаза → запись → саммари |
| Живые глаза и разные анимации | Векторные капсулы с изменяемой формой, направлением взгляда и веками |
| Открытие по наведению | Панель фокуса раскрывается вниз после 120 мс |
| Закрытие после ухода мыши | Через 450 мс после выхода из общей области компаньона и панели |
| Только три задачи | Жёсткое ограничение: максимум 3 активные задачи, без скрытого четвёртого слота |
| Задачи висят под notch | Компактные строки остаются видимыми, когда большая панель закрыта |
| Напоминания и сгорание | Ограниченные напоминания, срок каждой задачи, эмоциональное удаление из фокуса |
| Злится, плачет, сжигает, подметает, выбрасывает | Отдельный набор коротких реакций; одна реакция на событие |
| Свайпы двумя пальцами внутри компаньона | Влево: Фокус → Буфер → Записи; вправо — назад |
| Правая половина экрана | Буфер и записи используют одну закреплённую справа панель |
| Просмотр транскрибации и саммари | Саммари / Текст / Рядом; три формы саммари |

Исходный скриншот задаёт только чёрную основу, белые глаза и привязку к верхней части экрана. Исправить видимые недостатки: чрезмерную пустую высоту, обрезанный текст, слабую иерархию и необоснованное свечение.

## 3. Визуальная идея

**Спокойная точность macOS, характер — в глазах.**

- Правое крыло notch и полка задач под ним почти непрозрачные, сатиново-чёрные.
- Раскрывающиеся поверхности — дымчатое стекло, но текстовая область достаточно плотная для чтения.
- Цвет обозначает состояние. Синий — выбор; янтарный — приближение срока; коралловый — запись или истечение срока.
- Пластика интерфейса мягкая, движения короткие. Никакой непрерывной тряски, радужных ореолов или светящихся контуров вокруг всей панели.
- Персонаж не имеет головы, тела, рта, носа, радужки или ушей. Две простые белые капсулы должны узнаваемо сохраняться во всех состояниях.
- Обычный фон рабочего стола остаётся виден. Модального затемнения всего экрана нет.
- Пользовательский интерфейс на русском. Рабочее обозначение — «ИИ-компаньон»; отдельное название бренда не вводить.

Принцип материалов опирается на разделение переднего плана и фона, описанное в [Apple HIG: Materials](https://developer.apple.com/design/human-interface-guidelines/materials). Движение используется для обратной связи и состояния, как в [Apple HIG: Motion](https://developer.apple.com/design/human-interface-guidelines/motion). Это визуальные ориентиры; соответствие всей HIG и конкретной версии macOS не заявляется.

## 4. Геометрия и расположение

### 4.1. Система координат

Все размеры в логических pt, не в физических пикселях. Базовый макет: рабочая область шириной 1440 pt. Retina влияет на плотность отрисовки, но не удваивает логические размеры.

Для иллюстрации допустим условный notch 184 × 32 pt. В реализации его размеры нельзя фиксировать: положение корпуса вычисляется относительно доступной области конкретного экрана. Область аппаратной камеры не содержит рисуемого интерфейса.

| Элемент | Размер и положение |
| --- | --- |
| Правое крыло управления без задач | 164 × высота notch; бесшовно примыкает к его правой границе |
| Правое крыло управления с задачами | Те же размеры; не сдвигается при раскрытии focus |
| Стык notch и крыла | 0 pt; одинаковый цвет и нижняя линия; без границы, тени и скругления в месте соединения |
| Полка с 1 / 2 / 3 задачами | 288 × 32 / 56 / 80 pt; по центру под notch |
| Полка задач | 8 pt суммарных вертикальных отступов + 24 pt на активную задачу; без шапки глаз |
| Раскрытая панель фокуса | 376 × 260 pt при стандартном размере текста; без шапки глаз |
| Верх полки и раскрытой панели | На 4 pt ниже нижнего края notch; панель растёт вниз |
| Правая панель | Ширина 50% доступной рабочей области экрана |
| Отступ правой панели | 12 pt справа и снизу; сверху — 12 pt ниже самой нижней видимой поверхности компаньона |
| Высота правой панели | До нижнего края доступной области с отступом 12 pt; зависит от числа задач под notch |
| Панель на экране 1440 pt | Ширина 720 pt, левый край на 708 pt относительно начала области |
| Внутренние поля правой панели | 20 pt |
| Колонка списка записей | 180 pt; промежуток до содержимого 16 pt |
| Кнопки у глаз | Визуальная и интерактивная область 32 × 32 pt; иконка 14–16 pt |
| Глаза | Область 48 × 28 pt; каждая капсула 9 × 18 pt |
| Группа в правом крыле | Глаза 48 + промежуток 20 + кнопка 32 + промежуток 8 + кнопка 32 = 140 pt |

Группа шириной 140 pt помещается в правом крыле шириной 164 pt с полями по 12 pt. Само крыло начинается точно у правой границы notch: `wingLeft = notchRight`, `wingTop = notchTop`, `wingHeight = notchHeight`. Внутренний контент начинается на `wingLeft + 12`. Левая сторона крыла прямоугольная и визуально сливается с notch; скругляются только внешний правый верхний и правый нижний углы. Цвет, высота, верхняя и нижняя линии совпадают с notch. В месте соединения нет бордера, внутреннего блика, тени или разницы прозрачности. Вся интерактивная группа находится на доступных пикселях правее физической камеры. Задачи остаются на оси notch: `taskShelfLeft = notchCenterX − 144`, `taskShelfTop = notchBottom + 4`. Не раздвигать кнопки и глаза на противоположные края экрана.

### 4.2. Связь с notch и другими окнами

- Аппаратная область камеры остаётся пустой чёрной областью. Программное крыло начинается без зазора у её правой границы и продолжает силуэт notch на доступных пикселях строки меню. Под notch остаётся только полка задач или раскрытый focus.
- На экране без notch не рисовать поддельную камеру. Показывать самостоятельную капсулу шириной 164 pt по центру под строкой меню, с полноценным скруглением всех углов; задачи и focus — по центру экрана, на 4 pt ниже неё. Бесшовное крыло применяется только когда физический notch реально присутствует.
- Не перекрывать существующие системные индикаторы и меню. Если для крыла справа недостаточно доступной ширины, допустим явно описанный fallback: самостоятельная капсула опускается сразу под строку меню; вертикальное положение полки пересчитать ниже неё. Не возвращать глаза под центр камеры. Доступность места и поведение строки меню проверить на целевом Mac.
- На каждом экране показан только один экземпляр глаз и обеих кнопок. В focus и в большой правой панели второе лицо не дублировать.
- Выбранный экран сохраняется настройкой. При отключении монитора компаньон перемещается на основной доступный экран.
- Компактная и hover-панели не забирают клавиатурный фокус у активного приложения. Поле ввода получает его после явного клика.
- Правая панель располагается над обычными окнами и закрывает часть их содержимого. Рабочие окна не сдвигаются и не меняют размер.
- Прозрачные области за пределами фактической формы не должны перехватывать нажатия.
- Поведение поверх полноэкранных приложений, Spaces и системных окон требует отдельной проверки на целевых версиях macOS. Не обещать превосходство над защищёнными системными поверхностями.
- Когда правая панель открыта, правое крыло notch и компактная полка задач под notch остаются, а большая hover-панель автоматически не раскрывается.
- Для исключения пересечения правая панель начинается ниже обеих видимых поверхностей компаньона. Вычислить `companionBottom` как нижнюю из границ крыла и полки, привести её к координатам доступной рабочей области, затем `drawerTop = max(12, companionBottom + 12)`, `drawerHeight = availableHeight − drawerTop − 12`. Пример: начало рабочей области совпадает с нижней границей notch; полка начинается на y=4 и имеет высоту 80 pt, её низ y=84; drawer начинается на y=96 и при доступной высоте 900 pt имеет высоту 792 pt. Без задач учитывать только крыло и минимальный верхний отступ 12 pt. «Половина экрана» означает 50% ширины. При изменении числа задач пересчитывать размер; во время открытого drawer не перестраивать высоту раньше окончания текущего ввода или drag.

### 4.3. Адаптация

В обычном режиме сохранять ровно половину экрана. Если половина доступной ширины меньше 520 pt, разрешён адаптивный режим: ширина правой панели `min(520, W − 24)`, где W — доступная ширина. Это осознанное исключение для маленького экрана.

При ширине панели меньше 680 pt список записей заменяется кнопкой «Все записи», открывающей внутренний список. При увеличенном тексте строки фокуса могут вырасти до 72 pt, а высота панели — по содержимому; ограничение в три задачи сохраняется. Длинный текст переносится максимум на две строки в раскрытой панели.

Референс для имитации стекла: background blur 28 pt, белая внутренняя линия 1 физический пиксель, наружная тень 0 / 14 / 40 pt с чёрным 0.24. На нативной платформе использовать подходящий системный материал; конкретный API выбирать после проверки deployment target. Не накладывать несколько сильных blur-слоёв.

### 5.2. Типографика и размеры

Основной шрифт — системный macOS. Для веб-прототипа: `-apple-system, BlinkMacSystemFont, "SF Pro Text", system-ui, sans-serif`. Не распространять файлы SF Pro вместе с проектом без проверки соответствующих условий.

| Стиль | Размер / интерлиньяж | Насыщенность |
| --- | --- | --- |
| Заголовок записи | 20 / 26 pt | 600 |
| Заголовок панели | 16 / 22 pt | 600 |
| Основной текст транскрипта | 14 / 21 pt | 400 |
| Название задачи в раскрытой панели | 13 / 18 pt | 500 |
| Компактная задача | 11 / 15 pt | 500 |
| Метаданные, таймеры | 11 / 15 pt | 400 |
| Малые подписи | 10 / 14 pt | 500 |

Таймеры используют табличные цифры и не меняют ширину при обновлении. Минимальные поля строки — 12 pt в компактном виде и 16 pt в раскрытом.

Шкала отступов: 4, 8, 12, 16, 20, 24, 32 pt. Радиусы: кнопка 16; внешний правый край крыла `notchCornerRadius`; самостоятельная fallback-капсула 16; строка 10; полка задач 20; focus 24; правая панель 24. Использовать непрерывную кривизну, где она доступна.

## 6. Компактный режим

### 6.1. Глаза

Две белые вертикальные капсулы внутри 48 × 28 pt. В собственной области пары 42 × 26 pt: левый глаз x=8, правый x=25, оба y=4, ширина 9, высота 18. Область пары центрировать внутри 48 × 28 pt.

Обычный взгляд не сопровождается свечением. Движение глаз задаётся геометрией; не заменять их изображением эмодзи или видеороликом. Реакции должны воспроизводиться без ответа языковой модели.

### 6.2. Две кнопки

| Кнопка | Вид | Нажатие | Подсказка |
| --- | --- | --- | --- |
| Запись | Маленький коралловый круг внутри тонкого светлого кольца | Начать запись; при записи — остановить | «Начать транскрибацию» / «Остановить запись» |
| Саммари | Три короткие горизонтальные линии и маленькая четырёхлучевая искра | Саммаризировать текущую выбранную или последнюю доступную запись | «Сделать саммари: [название]» |

Иконки одного веса: приблизительно 1.5 pt. По возможности использовать соответствующие системные символы, проверив их наличие на целевой версии ОС. При отсутствии — собственные простые векторные иконки в том же стиле.

Кнопки всегда видимы, не появляются только по наведению. На hover — мягкое осветление круга. Нажатие — scale 0.94 на 80 мс. Tooltip появляется через 600 мс. Клик по кнопкам не считается кликом по глазам и не открывает focus.

При активной записи первая иконка превращается в небольшой квадрат остановки. При наличии свободного места правое крыло можно расширить до 212 pt для текстовой метки времени, сохраняя бесшовный стык с notch; не перекрывать системные элементы. Если места нет, время отображается в панели записи и tooltip. Напоминания не перекрывают кнопку остановки.

### 6.3. Постоянная полка задач

Три строки по 24 pt, без скролла. В строке: completion ring 12 pt, промежуток 8 pt, название, промежуток 8 pt, срок справа. Однострочное название обрезается многоточием; полное видно по наведению и в раскрытом виде.

Completion ring показывает действие «выполнить», а не процент якобы выполненной работы. Линия оставшегося срока — отдельная тонкая полоса высотой 1 pt, не похожая на прогресс работы.

Порядок задач закреплён пользователем; автоматической перестановки при приближении срока нет. Взгляд напоминающего персонажа направляется к соответствующей строке.

При нуле задач полки нет; правое крыло notch остаётся. При одной или двух задачах уменьшается только высота полки; пустые слоты показываются в раскрытой панели.

## 7. Панель фокуса

### 7.1. Layout 376 × 260 pt

Вертикальная сетка: блок заголовка 40 + три строки по 56 + промежуток 12 + подвал 40 = 260 pt. Прежняя шапка глаз высотой 44 pt удалена.

- Глаза и две кнопки остаются снаружи панели, в неподвижном правом крыле notch. Панель начинается сразу с заголовка.
- Заголовок «Сегодня в фокусе». Справа счётчик «3 / 3».
- Три слота: название; справа срок; снизу тонкая линия оставшегося времени. Время не дублируется огромными цифрами.
- В каждой строке есть отметка выполнения. Редактирование срока, смена порядка и удаление доступны через контекстное меню.
- Если слот свободен: спокойная строка «Добавить важное дело». Она считается одним из трёх слотов.
- Подвал: «Три дела. Одно внимание.» и малые кнопки «Фокус», «Буфер», «Записи».
- Архив завершённых и сгоревших задач открывается отдельным пунктом «История» в меню фокуса. Это не четвёртая задача и не дополнительный рабочий список.

### 7.2. Наведение, удержание и закрытие

| Событие | Поведение |
| --- | --- |
| Курсор вошёл в область глаз | Через 120 мс раскрыть focus, если не открыт drawer |
| Курсор покинул глаза до 120 мс | Отменить открытие |
| Курсор перешёл с глаз в строки | Сохранить раскрытие |
| Курсор покинул всё объединение корпуса и панели | Запустить таймер 450 мс |
| Курсор вернулся до истечения таймера | Отменить закрытие |
| Идёт ввод, drag или открыто меню | Не закрывать автоматически |
| Клик по глазам при закрытой панели | Открыть и закрепить focus |
| Клик по глазам в hover-панели | Закрепить focus |
| Повторный клик по глазам при закреплённом focus | Свернуть |
| Escape | Сначала закрыть меню/редактор, затем панель |
| Клик вне закреплённого focus | Закрыть после завершения редактирования |

Общая hover-область объединяет правое крыло, полку/focus и короткий коридор движения курсора между ними. При диагональном переходе от глаз к задачам таймер закрытия отменяется. Коридор используется только для отслеживания hover; прозрачные участки не перехватывают клики у других приложений. Вне этого коридора действует обычная задержка 450 мс.

Нельзя автоматически переключать пользователя с записей на focus при случайном наведении на глаза. При открытой правой панели явный клик по глазам закрывает её и открывает закреплённый focus.

## 8. Жесты и навигация

Страницы имеют неизменный порядок: **Фокус → Буфер → Записи**.

«Свайп влево» в этом документе означает физическое движение двух пальцев влево по трекпаду. Контент уходит влево, открывается следующая страница. В реализации нормализовать знак событий с учётом устройства и системного направления прокрутки.

| Откуда | Действие | Результат |
| --- | --- | --- |
| Компактный корпус или focus | Один свайп влево | Открыть правую панель на «Буфер» |
| Буфер | Следующий отдельный свайп влево | «Записи» в той же панели |
| Записи | Свайп вправо | «Буфер» |
| Буфер | Свайп вправо | Закрыть drawer, открыть закреплённый focus |
| Первая или последняя страница | Свайп за границу | Короткое сопротивление до 6 pt, без циклического перехода |
| Любая страница | Клик по названию страницы | Тот же результат без жеста |

Горизонтальное распознавание работает, только если жест начался внутри компаньона, focus или навигационной шапки drawer. Для списков, выделяемого текста, горизонтальных блоков кода и редакторов сохранять их обычные жесты.

Предлагаемый порог: накопленное горизонтальное смещение ≥40 pt и `abs(dx) ≥ 1.5 × abs(dy)`. Сначала определить ось, затем фиксировать её до завершения жеста. Один физический жест даёт максимум один переход; остаточная инерция не переключает следующую страницу.

Вертикальная прокрутка внутри буфера и записей прокручивает содержимое. Не перехватывать глобальные жесты Spaces и Mission Control. Конфликты обязательно проверить на реальном трекпаде.

Для мыши без трекпада и клавиатуры есть видимые кнопки страниц. При фокусе на переключателе стрелки влево/вправо меняют страницу; Tab переходит между контролами; Enter или Space активируют кнопку. Глобальные сочетания без проверки конфликтов не назначать.

При первых двух открытиях показать небольшую подсказку «Два пальца влево — буфер и записи». Затем скрыть. Подсказку можно отключить сразу.

## 9. Правая панель

### 9.1. Общая оболочка

Правая панель открывается только явным жестом, кликом или командой. Она не закрывается при уходе мыши через 450 мс: правило hover относится только к временному focus.

Верхняя строка 48 pt: переключатель «Фокус / Буфер / Записи», кнопки закрепления и закрытия. Закрепление включено по умолчанию. Закреплённая панель остаётся при клике в другое приложение. Незакреплённая закрывается при внешнем клике, сохраняя страницу, выделение и позицию чтения. Уход курсора сам по себе не закрывает drawer в обоих режимах.

Escape закрывает панель после закрытия внутренних меню. Явное закрытие возвращает визуально к компактному компаньону. Поле поиска и редактор получают клавиатурный фокус только по явному действию.

Переход между «Буфер» и «Записи» не создаёт вторую панель. Использовать одну оболочку, одну позицию и один механизм ресайза.

### 9.2. Буфер обмена

- Заголовок «Буфер», поиск «Поиск в буфере».
- Записи — текст, ссылка или изображение; монохромная пиктограмма типа, превью, источник/время только если эти сведения реально доступны.
- Текстовое превью занимает максимум три строки; ссылка — домен и заголовок, при отсутствии заголовка сам URL.
- Нажатие на строку раскрывает деталь внутри панели. Кнопка «Копировать» копирует; появляется подтверждение «Скопировано» на 1.5 с.
- Не вставлять содержимое автоматически в чужое приложение.
- Меню строки: «Закрепить», «Удалить». Общая настройка: «Пауза истории буфера».
- Пустое состояние: «Здесь появится скопированное».
- История буфера включается явным пользовательским действием. До включения показывать кнопку «Включить историю буфера».
- Содержимое буфера не становится задачей или запросом к модели автоматически. Для отправки в обработку нужно действие «Обработать».
- Для реализации предложен локальный лимит: 100 элементов или 7 дней, что наступит раньше; закреплённые исключены из автоматической очистки. Не обещать надёжное распознавание всех паролей и секретов.

### 9.3. Записи: список и чтение

Слева список записей шириной 180 pt. Строка: название, дата, длительность, статус «Запись / Обработка / Готово / Ошибка». Выбранная запись имеет мягкую синюю подложку.

Справа заголовок записи и реальные метаданные. Режимы:

| Режим | Содержимое |
| --- | --- |
| Саммари | Выжимка с блоками «Главное», «Решения», «Следующие шаги» |
| Текст | Транскрипт с временными метками, поиском и переходами |
| Рядом | Транскрипт слева, саммари справа |

Внутри «Саммари» доступны форматы «Кратко / Подробно / Действия». Это разные представления результата; для реализации необходимо определить, какие генерируются отдельно, и не выдавать отсутствующий результат за готовый.

«Рядом» требует минимум 640 pt ширины области чтения. При необходимости скрыть колонку списка записей. Если 640 pt недоступны, показывать транскрипт и саммари вертикально, с явными заголовками, сохраняя выбранный режим.

Следующий шаг из саммари имеет небольшую кнопку «В фокус». При трёх занятых слотах предложить выбрать задачу для замены или отменить добавление. Не добавлять четвёртую и не вытеснять текущую задачу молча.

Метки спикеров показывать только при наличии соответствующих данных. Не придумывать имена участников, временные метки, точные цитаты или подтверждения решений. Для выводов модели, которые нельзя связать с текстом, использовать нейтральное обозначение «Предположение».

## 10. Запись и саммаризация: состояния

| Состояние | Запись | Саммари | Контент |
| --- | --- | --- | --- |
| Нет материала | Доступна | Неактивна, tooltip «Сначала сделайте запись» | Спокойное пустое состояние |
| Выбор источника | Короткий popover | По наличию прошлых записей | «Микрофон / Системный звук / Оба», только доступные варианты |
| Требуется разрешение | Явный статус и понятное действие | Старые записи доступны | Не показывать, что запись уже идёт |
| Идёт запись | Квадрат остановки, таймер | Доступна после появления текста | Живой транскрипт, статус записи |
| Финальная транскрибация | Повторный старт согласно возможностям движка | Ждёт согласованного фрагмента | «Обрабатываю запись…» |
| Генерация саммари | Независимый контрол записи | Небольшой spinner вместо искры | «Готовлю саммари…», без выдуманного процента |
| Готово | Обычный вид | Можно обновить | Сохраняется результат |
| Ошибка | Состояние определяется источником ошибки | «Повторить» | Причина, retry, сохранённый исходный материал |

Первый запуск записи открывает компактный выбор источника, дальнейшие используют последний выбранный доступный источник. Настройка источника доступна через контекстное меню кнопки записи. Требуемые системные разрешения нельзя обходить или маскировать.

Если нажать саммаризацию во время записи, обрабатывать снимок уже полученного текста; запись продолжается. Результат подписать «По состоянию на 12:34». Новые фрагменты делают саммари устаревшим и показывают «Обновить». Финальная саммаризация начинается после завершения транскрибации либо по явному действию.

Приоритет выбора материала: открытая пользователем запись → активная запись → последняя запись с текстом. Tooltip всегда показывает выбранную цель. Повторные клики во время обработки не создают дубликаты задания.

Состояния записи, саммаризации, панели и эмоции независимы. Грустные глаза не означают остановку записи. Ошибка модели не должна скрывать транскрипт или удалять аудио.

Метка «Локальная обработка» в макете описывает целевой режим. В рабочем продукте показывать её только когда конкретная операция действительно выполняется локально. Подключение к Obsidian, календарю и другим источникам не входит в подтверждённый объём этой спецификации.

## 11. Задачи, сроки и сгорание

### 11.1. Добавление

Поля: короткое название (до 80 символов), срок и необязательная заметка. Основное действие — «В фокус». Срок обязателен и виден до сохранения. Пресеты 30 / 60 / 90 минут и «Выбрать время»; предлагаемый default — 60 минут.

Сгорание — прозрачное правило: при добавлении подпись «После срока задача уйдёт в историю». Это не необратимое удаление.

### 11.2. Жизненный цикл

| Состояние данных | Условие | Представление |
| --- | --- | --- |
| active | Задача в одном из трёх слотов | Обычная строка |
| active + dueSoon | До срока ≤10 минут или ≤20% исходного интервала | Янтарный таймер, краткий взгляд на строку |
| completed | Пользователь отметил выполнение | Галочка и короткая радостная реакция, затем история |
| expired | Срок наступил, задача не завершена | Один эффект сгорания/утилизации, освобождение слота, история |
| archived | Пользователь убрал задачу раньше срока | Спокойный уход в историю, без наказательной эмоции |

`dueSoon` — вычисляемый визуальный признак, а не отдельная активная задача. Линия срока равна `clamp((expiresAt − now) / (expiresAt − startedAt), 0, 1)`. Это доля оставшегося времени, не оценка готовности.

Нажатие «Готово» — единственное базовое подтверждение выполнения. ИИ может спросить «Это уже сделано?», но не знает ответа по одному факту бездействия. Интеграции в будущем могут предлагать подтверждение с объяснимым источником.

Редактирование срока не скрывать: «Перенести на 30 минут» обновляет начало интервала и новый срок, сохраняет событие переноса. Частые переносы не вызывают дополнительных обвинительных реплик.

При истечении срока сначала сохранить статус expired, затем воспроизвести эффект. Сбой анимации не должен потерять задачу. После эффекта текст «Задача сгорела» и кнопка «Вернуть» на 8 секунд. Позже восстановление доступно из истории. Восстановление требует нового срока и свободного слота; при заполненных трёх слотах пользователь выбирает замену.

Одновременно истёкшие задачи меняют статус вместе, но эффекты объединяются в один эпизод до 1.6 с. Нельзя проигрывать три длинных наказания подряд.

### 11.3. Напоминания

Предлагаемый режим по умолчанию:

- Первый тихий сигнал на 50% выбранного интервала.
- Второй сигнал за 5 минут до срока.
- Не более одного заметного напоминания на весь компаньон за 20 минут. Пропущенные сигналы объединяются, а не ставятся в очередь.
- Сигнал: взгляд к строке, один мягкий подъём века и небольшая подпись на 4 секунды. Панели не открываются сами.
- Текст: «Вернёмся к предложению?» или «До срока 5 минут». Не писать «Ты снова всё провалил».
- Возможна настройка «Чаще»: глобальный интервал 10 минут, максимум 4 заметных сигнала в час. «Тихо»: только изменение глаз и цвета срока.
- В режиме «Не беспокоить», во время набора текста в панели и при демонстрации экрана, если её состояние достоверно доступно, громкие/развёрнутые реакции подавляются.
- Звуки выключены по умолчанию. Обычное моргание не считается напоминанием.
- «Не напоминать 30 минут» подавляет сигналы, но не меняет срок задачи. Это явно указано в меню.

Сроки абсолютные. После сна или перезапуска сверить время: просроченные задачи перенести в историю, показать одно спокойное уведомление «Пока вас не было, истёк срок 2 задач». Не воспроизводить накопившиеся вспышки, плач и огонь.

## 12. Живые глаза и библиотека эмоций

Все тайминги — начальные значения для реализации. Проверять на реальном масштабе, а не только в увеличенном макете.

| Состояние | Форма и действие | Длительность / повтор |
| --- | --- | --- |
| Спокоен | Две капсулы 9 × 18 pt, едва заметный общий сдвиг | Непрерывной пульсации нет |
| Моргание | Высота 18 → 2 → 18 pt | 110 мс; интервал случайный 4–7 с |
| Смотрит на курсор | Общий сдвиг пары до ±3 pt по x, ±2 pt по y | Сглаживание 120 мс; только рядом с корпусом |
| Любопытен | Один глаз на 2 pt выше, другой слегка уже | 280 мс при входе курсора |
| Записывает | Спокойный устойчивый взгляд; минимальная реакция высоты на реальный уровень звука | Без фиктивной реакции, если уровень недоступен |
| Думает | Поочерёдное сужение глаз и короткий взгляд в сторону | Цикл 1.2 с, только при реальной обработке |
| Напоминает | Взгляд вниз к нужной задаче, короткий подъём века | 650 мс, один цикл |
| Радуется | Капсулы превращаются в две короткие улыбчивые дуги; подъём на 2 pt | 700 мс |
| Злится | Верхние веки наклонены внутрь, глаза ниже и уже; один короткий толчок 2 pt | 450 мс перед утилизацией |
| Грустит / плачет | Верхние края слегка опущены; одна маленькая полупрозрачная слеза | 800 мс; без повторного плача |
| Подметает | Взгляд следует за маленькой векторной щёткой, сметающей крошки задачи | 1100 мс |
| Комкает и выбрасывает | Строка становится бумажным фрагментом, сминается и уходит в маленькую корзину | 1300 мс |
| Ошибка | Короткая асимметрия взгляда, затем спокойный вид | 300 мс; сообщение объясняет причину |

Постоянных рук или тела нет. Для утилизации допустимы временные графические предметы: бумага, щётка, маленькая корзина. Они появляются только в области задачи и исчезают после действия.

### 12.1. Семейства реакции на истечение срока

Настройка характера: «Мягкий / Выразительный / Без эмоций». По умолчанию — «Выразительный», как в запросе пользователя.

Варианты:

1. **Сгорание:** злой взгляд → край строки тлеет → 6–10 маленьких частиц → строка исчезает.
2. **Бумага:** грустный взгляд → строка сминается → короткая дуга в корзину.
3. **Уборка:** взгляд вниз → небольшая щётка сдвигает остатки за край.

Один выбранный вариант на событие, не комбинация всех эффектов. При «Мягком» режиме оставить грустный взгляд и растворение бумаги без огня. При «Без эмоций» — обычное изменение статуса.

Реакция относится к исчезающей задаче. Не использовать угрозы, оскорбления и затяжное чувство вины как механику вовлечения.

### 12.2. Motion-токены

| Токен | Значение |
| --- | --- |
| hover.openDelay | 120 мс |
| hover.closeDelay | 450 мс |
| focus.expand | 220 мс |
| focus.collapse | 180 мс |
| drawer.open | 280 мс, сдвиг справа 32 → 0 pt + opacity |
| drawer.close | 220 мс |
| page.change | 240 мс, сдвиг до 24 pt + crossfade |
| feedback.press | 80 мс |
| standard.easing | cubic-bezier(0.2, 0.8, 0.2, 1) |
| disposal.maximum | 1600 мс |

Открытие focus меняет ширину полки 288 → 376 и высоту до 260 pt при стандартном тексте, сохраняя центральную привязку под notch. Масштаб текста не анимировать. Правое крыло с глазами и кнопками не перемещается и не растягивается вместе с focus; лиц-дубликатов нет. При пустом фокусе панель появляется из своей верхней привязки под notch.

При Reduce Motion: crossfade 100–150 мс, без сдвига панелей, тряски, частиц, слёз и летящей бумаги. Статус и кнопка восстановления сохраняются.

Приоритет эмоций: ошибка, требующая внимания → прямое действие пользователя → истечение срока → выполнение → напоминание → фоновая активность. Индикатор записи независим и всегда остаётся достоверным.

## 13. Доступность и производительность

- Каждой иконке задать доступное название. Глаза — кнопка «Открыть фокус», а не декоративное изображение без действия.
- Для маленьких completion rings расширить hit-area до 24 × 24 pt; у верхних кнопок — 32 × 32 pt. На пересечениях зон приоритет имеет видимый контрол.
- Не сообщать смысл одним цветом: срок написан текстом; запись имеет квадрат остановки и таймер; ошибка содержит объяснение.
- Цель контраста: не менее 4.5:1 для обычного текста, 3:1 для значимых контуров контролов. Проверять итоговый материал на светлом и тёмном фоне.
- Видимый keyboard-focus: тонкий синий контур с достаточным контрастом; не полагаться только на яркость серого.
- Screen reader сообщает изменения статуса, но не каждое моргание и каждую секунду таймера.
- У статичных глаз нет бесконечного рендера 60 fps. Анимации запускаются по событиям; паузы между морганиями не требуют непрерывного цикла рисования.
- Целевая плавность переходов — 60 fps на целевом Mac, без утверждения, что это уже достигнуто.
- Транскрибация и модель работают вне главного UI-потока. Их нагрузка не должна задерживать остановку записи.
- Эффекты не должны требовать видеоплеера, большого spritesheet или тяжёлого 3D-движка.

## 14. Модель состояния для повторения агентами

Разделить четыре независимые области:

| Область | Минимальные значения |
| --- | --- |
| panel | collapsed, focusHover, focusPinned, clipboard, recordings |
| capture | idle, selectingSource, needsPermission, recording, transcribing, error |
| summary | unavailable, readyToGenerate, generating, ready, stale, error |
| emotion | idle, curious, listening, thinking, reminder, happy, angry, sad, sweeping, discarding, error |

Минимальные данные задачи: `id, title, note, startedAt, expiresAt, status, order, completedAt, expiredAt, lastRemindedAt`. Статусы persisted: active / completed / expired / archived. Срок и события сохранять независимо от анимаций.

Минимальные данные записи: `id, title, createdAt, duration, source, captureStatus, transcriptVersion, transcriptSegments, summarySourceVersion, summaries, processingError`. Сегмент: начало, конец, текст, необязательная метка спикера. Неизвестные поля остаются отсутствующими.

Буфер: `id, type, contentReference, capturedAt, pinned, sourceLabel?`. Для изображения хранить ссылку на локальный ресурс, а не помещать большой бинарный объект в состояние интерфейса.

Для автоматизированного визуального воспроизведения нужны фиксированные fixture-состояния, замороженные таймеры и фиксированный seed случайного моргания. Не привязывать скриншоты к текущей дате или живому микрофону.

Это контракт интерфейса, а не предписание конкретной базы данных или фреймворка. Предпочтение для нативного macOS-приложения — системные окна/панели и векторная отрисовка; окончательную архитектуру определять после изучения проекта.

## 15. Канонические данные для макета

Использовать одинаковые данные на всех изображениях и в preview.

| Задача | Осталось | Порядок |
| --- | --- | --- |
| Отправить предложение | 18 мин | 1 |
| Закончить дизайн | 45 мин | 2 |
| Разобрать заметки | 1 ч 20 мин | 3 |

Первая задача в демонстрации имеет исходный интервал 90 минут: 18 минут составляют 20%, поэтому янтарное состояние соответствует правилу dueSoon.

Записи: «Встреча по проекту», «Идеи для компаньона», «Голосовая заметка». Выбрана первая: «Сегодня, 14:30 · 24 мин».

Пример саммари — демонстрационные данные, не реальный результат обработки:

- Главное: «Согласовали дизайн компаньона и три задачи в фокусе».
- Решения: «Записи и буфер открываются справа».
- Следующие шаги: «Подготовить прототип».

Буфер: ссылка «Документация проекта» и текст «Идея для следующей встречи».

## 16. Набор кадров и проверка результата

Обязательные состояния для реализации или последующего дизайнерского handoff:

1. Бесшовное правое крыло notch с глазами и кнопками без задач под ним.
2. То же правое крыло и отдельная полка трёх задач по центру под notch.
3. Раскрытый focus с тремя задачами и наведением.
4. Focus с одним свободным слотом.
5. Буфер: пустое состояние, список, деталь.
6. Записи: саммари, транскрипт, рядом.
7. Запись в процессе и отдельная генерация саммари.
8. Сгоревшая задача, восстановление и полный фокус.
9. Ошибка обработки и отсутствие разрешения.
10. Reduce Motion, Reduce Transparency, экран без notch.

Для первой сгенерированной иллюстрации достаточно четырёх составных панелей: компактный режим; desktop с правой панелью записей; крупный focus; буфер и набор эмоций. Изображение не доказывает работоспособность жестов или анимаций.

### Критерии приёмки

- [ ] В каждом состоянии лицо состоит из тех же двух белых капсул.
- [ ] Глаза и кнопки не находятся внутри аппаратной камеры.
- [ ] Глаза, запись и саммари целиком расположены в бесшовном правом продолжении notch, на одной высоте с ним.
- [ ] Между notch и правым крылом нет зазора, шва, отдельного левого скругления, тени или разницы цвета.
- [ ] При раскрытии focus правое крыло остаётся на месте; старой шапки с глазами под notch нет.
- [ ] Запись и саммари — ровно две маленькие кнопки справа от глаз.
- [ ] В компактном режиме три активные задачи остаются под notch.
- [ ] Большая панель не содержит огромной пустой чёрной области.
- [ ] Четвёртую задачу невозможно добавить без явной замены.
- [ ] Переход с глаз в панель не вызывает её закрытие.
- [ ] После ухода курсора hover-focus закрывается через 450 мс; возврат отменяет таймер.
- [ ] Открытая правая панель не закрывается по правилу hover.
- [ ] Жест влево открывает Буфер, следующий отдельный жест — Записи; инерция не перескакивает страницу.
- [ ] Есть видимая альтернатива каждому жесту.
- [ ] Drawer занимает половину доступной ширины в обычном режиме.
- [ ] Переключение страниц сохраняет позицию чтения и выбранную запись.
- [ ] Саммаризация не останавливает запись и не показывает выдуманный прогресс.
- [ ] ИИ не отмечает задачу выполненной без подтверждения или проверяемого источника.
- [ ] Сгоревшая задача доступна в истории; восстановление не нарушает лимит.
- [ ] Истечение срока во сне не запускает очередь наказательных анимаций.
- [ ] Утилизация длится не более 1.6 с и не закрывает остановку записи.
- [ ] Reduce Motion и клавиатура позволяют выполнить те же действия.
- [ ] На светлом и тёмном рабочем столе нет обрезанных надписей и нечитаемого текста.
- [ ] Реальные ограничения ОС и неподключённые интеграции не скрыты за демонстрационными статусами.

## 17. Указание следующему ИИ-агенту

Сначала прочитать весь документ и изучить существующий проект, если он предоставлен. Не переименовывать продукт и не менять базовую композицию по собственному вкусу. Сначала собрать статичные состояния на канонических данных, затем переходы и глаза, затем подключать функциональность.

Не начинать с чат-окна или большого dashboard. Не использовать изображение интерфейса как фон вместо настоящих контролов. Любые отклонения от размеров и поведения явно объяснить причиной: реальные ограничения экрана, доступность или согласованное изменение требований.

В отчёте разделять: реализовано; проверено на реальном устройстве; показано только демонстрационно; требует интеграции.
