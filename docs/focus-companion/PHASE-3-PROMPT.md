## Решения автора — приняты, не пересматривать

### 1. Ховер вместо NSTrackingArea, гибрид по кликам

`NSTrackingArea` требует, чтобы панель видела мышь, а `ignoresMouseEvents = true` —
это ровно то, что держит меню-бар кликабельным (критерий приёмки Фазы 1, проверен).

Поэтому:
- **свёрнутое состояние**: `ignoresMouseEvents = true`, наведение определяется
  по глобальной позиции курсора (попадание в прямоугольник капсулы);
- **раскрытое состояние**: `ignoresMouseEvents = false`, панель интерактивна
  (в Фазе 4 там будут чекбоксы задач);
- при сворачивании флаг возвращается в `true`.

**Критическая деталь:** глобальный монитор `NSEvent.addGlobalMonitorForEvents`
НЕ получает события, когда курсор над окном собственного приложения. Как только
раскрытая панель перестанет пропускать мышь, монитор ослепнет — и уход курсора
за пределы панели будет пропущен, панель зависнет раскрытой.

Поэтому определение наведения делать **опросом `NSEvent.mouseLocation` по
таймеру** (~20 Гц), а не через монитор. Опрос позиции дёшев: это чтение
состояния без обработки потока событий. Тот же опрос во время раскрытия должен
питать и слежение глаз, иначе взгляд замрёт, пока курсор над панелью.

### 2. Окно всегда в размере раскрытой панели

Анимировать `setFrame` окна синхронно с анимацией SwiftUI — источник рывков:
это два разных механизма с разными таймингами. Поэтому **панель постоянно
имеет размер раскрытого состояния**, а морфится только содержимое внутри —
чистая SwiftUI-анимация.

Следствия, которые обязаны быть учтены:
- капсула рисуется прижатой к ВЕРХУ окна и по центру по горизонтали, а не
  растянутой на весь фрейм (иначе форма разъедется);
- верхний край окна по-прежнему совпадает с верхним краем экрана;
- в раскрытом состоянии, когда `ignoresMouseEvents = false`, прозрачные поля
  окна НЕ должны глотать клики. Хит-тест ограничить формой капсулы:
  `.contentShape(NotchShape(...))` на содержимом, прозрачные области —
  `.allowsHitTesting(false)`. Это обязательно: окно теперь заметно больше
  капсулы, и ошибка здесь заблокирует существенный кусок экрана;
- `capsulePanelFrame` в `ScreenGeometry` теперь считает размер ОКНА (раскрытый),
  а размеры самой капсулы (свёрнутой и раскрытой) — параметры конфига.

### 3. matchedGeometryEffect НЕ использовать

Он нужен, когда вью переезжает между двумя разными иерархиями. Глаза же
существуют в единственном экземпляре и никуда не исчезают — достаточно
анимировать их положение и размер. `matchedGeometryEffect` при неудачном ID
даёт ровно тот скачок, которого требуется избежать.

## Что сделать

### `State/CompanionState.swift`

```swift
enum CompanionState {
    case idle         // спокойный
    case listening    // слушает (задел под транскрибацию, Фаза 5)
    case thinking     // обрабатывает
    case reminding    // мягко напоминает
    case annoyed      // раздражён ИГРИВО (см. «Тон» ниже)
    case celebrating  // радуется выполненной задаче
    case burning      // режим сжигания задачи (Фаза 4)
}
```

### `State/StateAppearance.swift`

Для каждого состояния — набор визуальных параметров, ВСЕ в конфиге, чтобы автор
крутил их без правки логики:

- форма глаз: множители к `eyeWidth`/`eyeHeight` (даёт прищур / округлость /
  раскрытые глаза), наклон в градусах;
- цвет подсветки состояния и её интенсивность;
- характер движения: множитель к частоте дыхания, к частоте моргания,
  к частоте и амплитуде саккад.

Ориентиры (автор потом подгонит):

| Состояние | Глаза | Подача |
|---|---|---|
| `.idle` | как сейчас | ровное дыхание |
| `.listening` | шире, раскрытые | подсветка, дыхание чаще |
| `.thinking` | прищур, взгляд уходит вбок | медленные саккады |
| `.reminding` | обычные | мягкая пульсация подсветки |
| `.annoyed` | прищур, лёгкий наклон | подчёркнутые «вздохи» |
| `.celebrating` | дуги-полумесяцы (перевёрнутые) | быстрое подпрыгивание |
| `.burning` | сузились | тёплая подсветка снизу |

### `State/CompanionStateMachine.swift`

`@MainActor @Observable`. Хранит текущее состояние, умеет переключать с
анимацией. Переходы анимированные, без резких скачков: смена формы глаз и
цвета подсветки идёт через `withAnimation` с внятной длительностью из конфига.

Учесть: `EyesViewModel` уже владеет своими циклами; машина состояний должна
ВЛИЯТЬ на их параметры (частота моргания, амплитуда саккад), а не дублировать
их. Способ связи на твоё усмотрение, но без второго набора таймеров.

### `Interaction/HoverDetector.swift`

`@MainActor @Observable`. Таймер ~20 Гц, читает `NSEvent.mouseLocation`,
проверяет попадание в текущий активный прямоугольник (свёрнутая капсула или
раскрытая панель — в глобальных координатах экрана).

- **задержка перед раскрытием ~0.2 сек** — чтобы пролёт курсора мимо не
  раскрывал панель. Обязательное требование ТЗ;
- задержка перед сворачиванием (короткая, ориентир 0.15 сек) — чтобы дрожание
  курсора у самой границы не давало мигания «раскрылось-свернулось»;
- параметры задержек — в конфиг.

### `UI/ExpandedPanelView.swift`

Содержимое раскрытой панели. В Фазе 3 там ещё нет задач — сделай осмысленную
заготовку: персонаж сверху, под ним область под контент Фазы 4. Пустая область
не должна выглядеть как ошибка отрисовки.

### `UI/NotchRootView.swift` (правка)

Морф между свёрнутым и раскрытым: размеры капсулы и радиусы формы
анимируются (`NotchShape.animatableData` для этого и делался), глаза плавно
переезжают и меняют масштаб. Никаких переключений вью через `if` там, где
можно анимировать значение — иначе будет скачок.

### `App/AppDelegate.swift` (правка)

**Debug-меню — это критерий приёмки фазы.** В меню статус-айтема `FC` добавить
подменю со всеми состояниями: выбор пункта переключает состояние персонажа.
Текущее состояние отмечено галочкой.

## Тон персонажа — обязательное требование, не смягчать

У людей с СДВГ часто повышена чувствительность к критике. Поэтому:

- `.annoyed` — **самоироничное и игровое** раздражение: персонаж мается от
  скуки («я тут с ума схожу»), а НЕ укоряет пользователя («ты опять ничего не
  сделал»). Визуально: скучающий прищур, вздохи — не сведённые «злые» брови;
- никакого стыда, счётчиков провалов, «стриков», которые рвутся;
- `.celebrating` по амплитуде и яркости должен быть **заметно сильнее**, чем
  `.annoyed`. Позитив громче негатива — это прямое требование автора.
